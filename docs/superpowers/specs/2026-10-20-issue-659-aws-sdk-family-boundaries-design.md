# 이슈 #659 AWS SDK 계열 경계 설계

- 날짜: 2026-10-20
- 저장소: `bluetape4k/bluetape4k-aws`
- 이슈: [#659](https://github.com/bluetape4k/bluetape4k-aws/issues/659)
- 상태: 설계 방향 승인됨; IMDS 원격 HTTP endpoint 제한 제안도 2026-10-20 사용자 승인됨. 명세 독립 검토와 사용자 최종 문서 확인 대기.
- ABI: 바이너리 호환성을 보장하지 않는다. 사용자가 이 작업의 ABI 파괴를 허용했다.

## 문제와 목표

이슈 #659는 `aws-ktor`가 AWS Kotlin SDK 계열을 사용하고 `aws-spring-boot`가 AWS Java SDK v2 계열을 사용하도록 의존 경계를 정리한다. 현재 `aws-ktor/build.gradle.kts`는 두 내부 wrapper 모듈을 모두 `api`로 노출하고, Java SDK 서비스 라이브러리도 다수 `api`로 선언한다. `aws-ktor/src/main/kotlin`의 50개 파일에서 `software.amazon.awssdk`를 참조한다. 공개 Ktor 설정, 서비스 작업, 모델, 실행 구성에서 Java SDK 타입을 노출한다.

`aws-ktor`의 테스트와 Ktor 예제도 Java SDK 클라이언트와 모델을 사용한다. 루트 `build.gradle.kts`는 SQS 소비자를 Java fixture로 컴파일한다. 반면 `aws-spring-boot/build.gradle.kts`는 이미 `bluetape4k-aws-java`를 `api`로 사용하며, AWS Kotlin SDK 코드 참조는 없다. Kotlin 의존 선언은 주석으로만 남아 있다. `aws-ktor/README.md`와 루트 README는 현재 Java 의존이 Ktor 공개 API에 전이되는 계약을 설명한다.

이번 변경의 목표는 다음과 같다.

1. Ktor 모듈의 자체 서비스 통합과 공개 AWS 서비스 타입을 AWS Kotlin SDK 계열로 옮긴다.
2. Spring Boot 모듈은 AWS Java SDK v2 계열을 유지하고 Kotlin SDK 의존 선언을 제거한다.
3. 클라이언트 소유권, 애플리케이션 종료, 취소, 요청 매핑, S3 서명, SQS 처리 의미를 유지한다.
4. Ktor 테스트·예제·외부 소비자 fixture와 영문/한국어 의존성 안내를 새 공개 API에 맞춘다.
5. 생성한 POM/Gradle 메타데이터에서 `aws-ktor`의 Java SDK 의존이 사라졌음을 검증한다.

## 기준 정보

### 저장소 증거

- [`aws-ktor/build.gradle.kts`](../../../aws-ktor/build.gradle.kts)는 `bluetape4k-aws-java`와 `bluetape4k-aws-kotlin`을 모두 `api`로 선언한다. CloudWatch, CloudWatch Logs, EventBridge, IMDS, Kinesis, S3 Control, S3 Vectors, SES v2, SNS, SQS, STS의 Java SDK 의존성도 공개한다. DynamoDB는 이미 AWS Kotlin SDK를 사용한다.
- `aws-ktor/src/main/kotlin/io/bluetape4k/aws/ktor/AwsKtorCore.kt`는 서비스별 Java 클라이언트 빌더 사용자 설정 함수를 공개 설정으로 보관한다. 서비스 패키지는 `PluginConfig`, `Operations`, `Template`, `Runtime`에서 Java 클라이언트와 모델을 사용한다.
- `client/AwsSigV4Plugin.kt`와 `s3/S3KtorClient.kt`는 AWS Java SDK 서명 API로 Ktor 요청을 서명한다. 본문 재생성, payload 서명 설정, URL/query 정규화와 사용자 정의 헤더 적용을 보존해야 한다.
- `sqs/SqsConsumerRuntime.kt`는 Java `SqsAsyncClient`, `CompletableFuture`, Java SQS 모델을 이용한다. 현재 동작에는 장기 폴링, 취소, 수동 ack/nack, 재시도, 관찰자 콜백과 종료 처리가 포함된다.
- `imds/ImdsKtorRuntime.kt`는 Java `Ec2MetadataAsyncClient`를 플러그인 소유 리소스로 등록하고 한 번 닫는다.
- `aws-ktor`의 외부 사용 경로는 `examples/aws-ktor-dynamodb-examples`, `examples/aws-ktor-exposed-examples`, `examples/aws-ktor-s3-examples`, `examples/aws-ktor-service-coverage-examples`, `examples/aws-ktor-sqs-examples`, 그리고 `aws-ktor/src/consumerFixture/java`다. 다섯 예제의 빌드 파일·테스트·README와 SQS Java consumer fixture가 마이그레이션 범위다.
- `aws-ktor/README.md`는 현재 Java/Kotlin 래퍼와 Java 서비스 SDK가 POM의 컴파일 의존성임을 설명한다. 루트 `README.md`와 `README.ko.md`에는 Ktor 서비스 범위와 모듈 구성이 기록되어 있다.
- `aws-spring-boot/build.gradle.kts`는 `bluetape4k-aws-java`만 실제로 선언한다. `bluetape4k-aws-kotlin`은 주석이며 Spring 소스의 Kotlin SDK import는 없다.
- `gradle/libs.versions.toml`에는 필요한 AWS Kotlin 서비스 별칭이 다수 있지만 S3 Control과 S3 Vectors 별칭이 없다. AWS Kotlin 서비스 별칭이 이 저장소의 `libs` 카탈로그에 있으므로 두 서비스의 별칭을 이 저장소에 추가한다. AWS Kotlin IMDS 클라이언트에 필요한 `aws-config` 별칭은 이미 있다.
- [`2026-05-17-issue-85-aws-ktor-migration-design.md`](2026-05-17-issue-85-aws-ktor-migration-design.md)는 당시 SigV4/S3의 Java 예외와 SQS 이관 연기를 결정했다. 이슈 #659가 해당 경계를 변경하므로 구현 전 역사 문서에 새 결정으로 대체되었음을 표시한다.

### 외부 API 근거

AWS Kotlin SDK 공식 API는 [CloudWatch](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/cloudwatch/aws.sdk.kotlin.services.cloudwatch/), [CloudWatch Logs](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/cloudwatchlogs/aws.sdk.kotlin.services.cloudwatchlogs/), [EventBridge](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/eventbridge/aws.sdk.kotlin.services.eventbridge/), [Kinesis](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/kinesis/aws.sdk.kotlin.services.kinesis/), [S3 Control](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/s3control/aws.sdk.kotlin.services.s3control/), [S3 Vectors](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/s3vectors/aws.sdk.kotlin.services.s3vectors/), [SES v2](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/sesv2/aws.sdk.kotlin.services.sesv2/), [SNS](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/sns/aws.sdk.kotlin.services.sns/), [SQS](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/sqs/aws.sdk.kotlin.services.sqs/), [STS](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/sts/aws.sdk.kotlin.services.sts/) 클라이언트를 제공한다. [IMDS `ImdsClient`](https://docs.aws.amazon.com/sdk-for-kotlin/api/latest/aws-config/aws.sdk.kotlin.runtime.config.imds/-imds-client/)는 서비스 클라이언트가 아니라 `aws-config` 실행 구성 API다. 고정 `1.8.46` 공개 endpoint mode 타입은 [`EndpointMode`](https://github.com/aws/aws-sdk-kotlin/blob/33dde8ef361cfd5b55d2ea283be7c728321c2956/aws-runtime/aws-config/common/src/aws/sdk/kotlin/runtime/config/imds/ImdsClient.kt#L1060-L1097)이며 값은 `IPv4`와 `IPv6`다. 이 SDK 구현은 IMDS transport에 [`ProxySelector.NoProxy`](https://github.com/aws/aws-sdk-kotlin/blob/33dde8ef361cfd5b55d2ea283be7c728321c2956/aws-runtime/aws-config/common/src/aws/sdk/kotlin/runtime/config/imds/ImdsClient.kt#L74-L82)를 사용한다.

저장소 `settings.gradle.kts`의 기본 catalog 참조 `198147fd6ca2992fae32e175bd5f3d396c497096`은 AWS Kotlin `1.8.46`과 Smithy Kotlin `1.7.9`를 지정한다. 이에 맞춰 AWS SDK Kotlin 릴리스 커밋 [`33dde8ef361cfd5b55d2ea283be7c728321c2956`](https://github.com/aws/aws-sdk-kotlin/commit/33dde8ef361cfd5b55d2ea283be7c728321c2956)과 Smithy Kotlin 릴리스 커밋 [`6106ef2e27a11e3c4df40058b98599c31924a4ec`](https://github.com/smithy-lang/smithy-kotlin/commit/6106ef2e27a11e3c4df40058b98599c31924a4ec)를 확인했다. 설정은 catalog 참조 재정의를 허용하므로 구현 계획에서 실제 Gradle 해결 버전과 해당 artifact의 공개 API를 다시 고정한다.

누락된 AWS Kotlin `s3control`과 `s3vectors` aliases는 versionless로 두고 루트 dependency-management에서 중앙 catalog의 `aws-kotlin=1.8.46`로 제약한다. 새 Smithy aliases는 로컬 `aws-smithy-kotlin=1.7.9` version ref를 사용하며, 기존 로컬 `1.6.14` 값을 그대로 사용하지 않는다. dependency declarations 뒤 `dependencyInsight`로 실제 해결 버전을 검증한다.

- IMDS: [`ImdsClient`](https://raw.githubusercontent.com/aws/aws-sdk-kotlin/33dde8ef361cfd5b55d2ea283be7c728321c2956/aws-runtime/aws-config/common/src/aws/sdk/kotlin/runtime/config/imds/ImdsClient.kt#L57-L78)와 [빌더](https://raw.githubusercontent.com/aws/aws-sdk-kotlin/33dde8ef361cfd5b55d2ea283be7c728321c2956/aws-runtime/aws-config/common/src/aws/sdk/kotlin/runtime/config/imds/ImdsClient.kt#L145-L178)는 6시간 `tokenTtl`, 기본 `maxRetries=3`, endpoint/mode 재정의, 주입 `HttpClientEngine`을 제공한다. 기본 엔진에는 연결/읽기 제한 시간 1초와 프록시 미사용 설정이 있고, 주입 엔진은 `ImdsClient.close()`가 닫지 않는다. [토큰 미들웨어](https://raw.githubusercontent.com/aws/aws-sdk-kotlin/33dde8ef361cfd5b55d2ea283be7c728321c2956/aws-runtime/aws-config/common/src/aws/sdk/kotlin/runtime/config/imds/TokenMiddleware.kt#L20-L65)는 토큰을 캐시하고 만료 전에 갱신한다. 그러나 현재 Java 설정의 `retries=0`은 재시도 없음이고 작업별 `requestTimeout`은 별도 코루틴 시간 제한이다. Kotlin `1.8.46` 소스는 `maxRetries <= 0`을 거부하고, 빌더 값을 `ImdsRetryPolicy`에 전달하지 않는다. 따라서 `ImdsClient`에 직접 매핑할 수 있다고 가정하지 않는다. 정확한 재시도 수와 작업별 시간 제한을 보존하는 Kotlin 전용 어댑터를 설계·검증하거나, 동등성을 입증하지 못하면 구현 전 차단 사유로 처리한다. 관련 [재시도 정책](https://raw.githubusercontent.com/aws/aws-sdk-kotlin/33dde8ef361cfd5b55d2ea283be7c728321c2956/aws-runtime/aws-config/common/src/aws/sdk/kotlin/runtime/config/imds/ImdsRetryPolicy.kt#L13-L29)과 [Smithy 엔진 timeout 설정](https://docs.aws.amazon.com/smithy-kotlin/api/latest/http-client/aws.smithy.kotlin.runtime.http.engine/-http-client-engine-config/to-builder-applicator.html)도 확인했다.
- 현재 해결된 Java IMDS artifact는 Gradle `dependencyInsight`에서 `software.amazon.awssdk:imds:2.54.12`로 확인했다. 이하 계약은 AWS SDK Java v2 고정 commit [`ee0bb9f4854fd2ccf1841e2cf36dafb416520161`](https://github.com/aws/aws-sdk-java-v2/commit/ee0bb9f4854fd2ccf1841e2cf36dafb416520161) 소스를 기준으로 한다.
  - 재시도: [`AsyncHttpRequestHelper`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/imds/src/main/java/software/amazon/awssdk/imds/internal/AsyncHttpRequestHelper.java)는 5xx만 retryable로 분류한다. 다른 비성공 상태는 401과 3xx를 포함해 재시도하지 않는다. [`BaseEc2MetadataClient`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/imds/src/main/java/software/amazon/awssdk/imds/internal/BaseEc2MetadataClient.java)는 `RetryableException` 또는 그 직접 cause만 재시도한다. `retries=0`은 총 1회, `N`은 최대 `N`회의 추가 operation 시도다. [`Ec2MetadataRetryPolicy`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/imds/src/main/java/software/amazon/awssdk/imds/Ec2MetadataRetryPolicy.java)는 `RetryMode.STANDARD` 기본 backoff를 지정한다. 고정 [`SdkDefaultRetrySetting`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/sdk-core/src/main/java/software/amazon/awssdk/core/internal/retry/SdkDefaultRetrySetting.java)은 표준 retry base를 100ms, cap을 20초로 정하고, [`BackoffStrategy`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/sdk-core/src/main/java/software/amazon/awssdk/core/retry/backoff/BackoffStrategy.java)와 [`FullJitterBackoffStrategy`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/sdk-core/src/main/java/software/amazon/awssdk/core/retry/backoff/FullJitterBackoffStrategy.java)는 full jitter를 적용한다. `DefaultEc2MetadataAsyncClient`가 실패 뒤 시도 횟수를 먼저 증가시키므로 재시도 cap은 200ms, 400ms, 800ms, 1600ms, 3200ms, 6400ms, 12800ms, 이후 20초로 제한된다. 각 지연은 1ms부터 해당 cap까지의 균등 난수다. 기존 Java 사용자 지정 HTTP client에 따른 transport 오류 차이는 새 전용 Smithy engine의 명시 계약으로 정하지 않는다. 이 이행의 transport 분류는 아래 별도 matrix에 고정한다.
  - 토큰: [`AsyncTokenCache`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/imds/src/main/java/software/amazon/awssdk/imds/internal/AsyncTokenCache.java)는 만료 시 토큰을 갱신한다. 조기 갱신 buffer나 401 응답에 따른 캐시 무효화는 없다.
  - endpoint: [`Ec2MetadataConfigProvider`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/imds/src/main/java/software/amazon/awssdk/imds/internal/Ec2MetadataConfigProvider.java)는 plugin 명시 endpoint, SDK system setting, profile, mode 기본 주소 순으로 선택한다. system setting은 JVM property가 대응 환경 변수보다 우선한다: `aws.ec2MetadataServiceEndpoint` / `AWS_EC2_METADATA_SERVICE_ENDPOINT`, profile `ec2_metadata_service_endpoint`. endpoint mode도 `aws.ec2MetadataServiceEndpointMode` / `AWS_EC2_METADATA_SERVICE_ENDPOINT_MODE`, profile `ec2_metadata_service_endpoint_mode`, SDK 기본값 순이다. 이 plugin은 `IPV4`를 기본 mode로 전달하므로 endpoint가 없을 때 SDK의 mode 선택값은 기본 주소를 바꾸지 않는다. 명시 endpoint는 이 기본값보다 우선한다. 고정 [`SdkSystemSetting`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/sdk-core/src/main/java/software/amazon/awssdk/core/SdkSystemSetting.java)과 [`SystemSetting`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/utils/src/main/java/software/amazon/awssdk/utils/SystemSetting.java)에서 이름과 property 우선순위를 확인했다.
  - timeout과 proxy: connect/read timeout은 JVM property `aws.ec2MetadataServiceTimeout`, 환경 변수 `AWS_METADATA_SERVICE_TIMEOUT`, active profile의 `metadata_service_timeout`, SDK 기본값 순으로 정해진다. JVM property는 환경 변수보다 우선한다. timeout은 정수/실수 초로 읽고 실수는 millisecond 단위로 반올림하며, 숫자가 아닌 값은 `IllegalStateException`이다. `requestTimeout`은 token 요청부터 응답 파싱까지 작업 전체를 별도로 제한한다. Java 구현은 no-proxy를 강제하지 않으며 HTTP client 설정을 사용한다.
  - profile 읽기 계약: 저장소 소유 `ImdsProfileResolver`가 AWS Kotlin `@InternalSdkApi` loader와 internal `ImdsEndpointProvider` 대신 기본 AWS shared profile 파일에서 세 scalar key만 읽는다. active profile은 JVM property `aws.profile` > 환경 변수 `AWS_PROFILE` > `default`다. config 경로는 property `aws.configFile` > `AWS_CONFIG_FILE` > `~/.aws/config`, credentials 경로는 property `aws.sharedCredentialsFile` > `AWS_SHARED_CREDENTIALS_FILE` > `~/.aws/credentials`다. 경로의 `~/`를 user home으로 확장하고 읽을 수 있는 regular file만 입력으로 취급한다. config의 `[default]`/`[profile <name>]`, credentials의 `[default]`/`[<name>]` section에서 `ec2_metadata_service_endpoint`, `ec2_metadata_service_endpoint_mode`, `metadata_service_timeout`만 읽는다. config에서 선택 profile이 `default`이면 `[profile default]`가 `[default]`보다 우선하며, 같은 파일과 profile에 key가 여러 번 나오면 마지막 값이 우선한다. 기본 aggregator는 credentials file을 먼저 merge하므로 두 파일에 같은 profile/key가 있으면 credentials 값이 우선한다. timeout은 정수/실수 초로 읽고 실수는 millisecond로 반올림하며 숫자가 아닌 값은 `IllegalStateException`이다. section parser는 일반 profile 상속·credential/role/SSO resolution을 구현하지 않는다. 숫자·profile source는 주입 가능한 test seam으로 검증한다. 근거: [AWS Java `ProfileFile`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/profiles/src/main/java/software/amazon/awssdk/profiles/ProfileFile.java), [`ProfileFileSystemSetting`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/profiles/src/main/java/software/amazon/awssdk/profiles/ProfileFileSystemSetting.java), [`ProfileFileLocation`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/profiles/src/main/java/software/amazon/awssdk/profiles/ProfileFileLocation.java), [`ProfileProperty`](https://github.com/aws/aws-sdk-java-v2/blob/ee0bb9f4854fd2ccf1841e2cf36dafb416520161/core/profiles/src/main/java/software/amazon/awssdk/profiles/ProfileProperty.java).
  - Smithy Kotlin `1.7.9` 고정 OkHttp engine은 모든 `IOException`을 retryable metadata가 설정된 `HttpException`으로 감싸며, 기본 엔진 구성에서 redirect와 SSL redirect를 비활성화한다. `HttpException` 생성자의 `retryable` 인자는 직접 읽는 프로퍼티가 아니며 공개 판정은 [`sdkErrorMetadata.isRetryable`](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/runtime-core/common/src/aws/smithy/kotlin/runtime/Exceptions.kt#L723-L794)이다. [`HttpException`](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/protocol/http/common/src/aws/smithy/kotlin/runtime/http/HttpException.kt#L427-L491)은 `CONNECT_TIMEOUT`과 `TLS_NEGOTIATION_TIMEOUT`을 metadata상 retryable로 표시하며, OkHttp의 IOException 변환은 생성자에 `retryable=true`를 전달한다. 이 계약은 [OkHttp 예외 매핑](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/protocol/http-client-engines/http-client-engine-okhttp/jvm/src/aws/smithy/kotlin/runtime/http/engine/okhttp/OkHttpUtils.kt)과 [engine 구현](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/protocol/http-client-engines/http-client-engine-okhttp/jvm/src/aws/smithy/kotlin/runtime/http/engine/okhttp/OkHttpEngine.kt)에서 확인했다. 전용 engine은 `retryOnConnectionFailure=false`로 구성해 외부 재시도 횟수에 포함되지 않는 연결 재시도를 막는다.
  - IMDS adapter의 고정 retry matrix: 5xx 응답과 `HttpException.sdkErrorMetadata.isRetryable == true`인 transport 실패는 재시도한다. OkHttp engine의 현재 매핑상 connect/read/socket timeout, TLS handshake를 포함한 모든 `IOException`이 재시도 대상이다. `CONNECT_TIMEOUT`과 `TLS_NEGOTIATION_TIMEOUT`은 Smithy error metadata 규칙으로 retryable이며, 그 밖의 HTTP exception은 `sdkErrorMetadata.isRetryable` 값으로 판정한다. 3xx, 401을 포함한 기타 4xx, 나머지 HTTP 상태, metadata가 retryable이 아닌 예외는 terminal이다. 취소와 `requestTimeout`에 따른 `CancellationException`은 retry하지 않고 그대로 전파한다. `retries=N`은 token 획득과 metadata 요청을 포함한 전체 `get/getList` operation을 최초 요청 뒤 최대 N회 더 시도한다. 재시도 지연은 Java 기본 표준 정책의 full-jitter 상한을 따른다. retry index별 upper bound는 200ms, 400ms, 800ms, 1600ms, 3200ms, 6400ms, 12800ms, 이후 20초이며 실제 delay는 1ms부터 각 상한까지다. 전체 `withTimeout(requestTimeout)`이 매 시도와 대기 시간을 제한한다. 이 transport 정책은 기존 사용자 지정 Java HTTP client가 제공하던 임의의 exception 매핑을 보존한다고 주장하지 않으며 새 동작으로 회귀 검증한다.
  - adapter는 token, endpoint 설정 우선순위와 HTTP timeout 설정을 보존한다. transport 분류와 redirect 정책은 이 표에 정한 Smithy engine 계약을 사용한다. Kotlin `ImdsClient`의 builder `maxRetries`에 의존하지 않는다.
- Smithy Kotlin `1.7.9` 고정 source의 [`SdkHttpClient.call(HttpRequestBuilder)`](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/protocol/http-client/common/src/aws/smithy/kotlin/runtime/http/SdkHttpClient.kt#L25-L30)는 공개 API다. 반환된 [`HttpCall.complete()`](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/protocol/http/common/src/aws/smithy/kotlin/runtime/http/HttpCall.kt#L55-L72)는 `public`이지만 `@InternalApi`로 표시되어 있으며 응답 자원 종료에 필요하다. adapter는 호출과 자원 정리를 좁은 내부 경계에 격리하고 실제 해결 버전에 고정한 컴파일·수명 주기 검증을 포함한다. 이 내부 API opt-in을 받아들일 수 없거나 버전 변경 때 계약을 보장할 수 없으면 구현 계획에서 중단한다.
- 공개 Smithy 타입은 resolved Smithy `1.7.9`의 `aws.smithy.kotlin:aws-credentials`, `aws-signing-common`, KMP root `http-client`를 사용하며 `api` 범위로 선언한다. Gradle JVM 소비자는 root의 JVM variant `http-client-jvm`을 선택한다. plugin 소유 IMDS engine은 KMP root `aws.smithy.kotlin:http-client-engine-okhttp`를 `implementation`으로 사용하며 JVM variant는 `http-client-engine-okhttp-jvm`이다. catalog alias와 root coordinate를 사용하고, POM·Gradle module metadata·외부 consumer compile fixture에서 scope와 선택 variant를 확인한다. `HttpCall.complete()`는 `http-client`의 공개 결과 타입에 필요한 내부 구현 호출이며 외부 API로 노출하지 않는다.
- 자격 증명: Smithy [`CredentialsProvider`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-credentials/common/src/aws/smithy/kotlin/runtime/auth/awscredentials/CredentialsProvider.kt#L9-L26)는 suspend `resolve()`를 제공한다. [`Credentials`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-credentials/common/src/aws/smithy/kotlin/runtime/auth/awscredentials/Credentials.kt#L15-L58)는 access key, secret key, 선택적 session token과 만료 시각을 보관한다. [`AwsSigner`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-common/common/src/aws/smithy/kotlin/runtime/auth/awssigning/AwsSigner.kt#L9-L43)는 resolve한 자격 증명을 입력으로 받으며 자동 갱신하지 않는다. 갱신은 provider가 `resolve()`할 때 제공자 구현 또는 [`CachedCredentialsProvider`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-credentials/common/src/aws/smithy/kotlin/runtime/auth/awscredentials/CachedCredentialsProvider.kt#L18-L68)가 담당한다.
- 자격 증명 제공자 수명 주기: 일반 Smithy `CredentialsProvider`는 `IdentityProvider`를 구현하지만 반드시 닫을 수 있는 것은 아니다. Smithy가 별도 하위 형식으로 제공하는 `CloseableCredentialsProvider`는 `Closeable`을 구현하며 사용 후 닫도록 명시한다([고정 소스](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-credentials/common/src/aws/smithy/kotlin/runtime/auth/awscredentials/CredentialsProvider.kt#L18-L26)). `CachedCredentialsProvider`는 닫을 수 있고 `close()`에서 원본 제공자가 닫을 수 있는 경우 함께 닫는다([고정 소스](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-credentials/common/src/aws/smithy/kotlin/runtime/auth/awscredentials/CachedCredentialsProvider.kt#L49-L68)). 따라서 호출자가 주입한 제공자를 캐시 wrapper에 넣고 플러그인이 wrapper를 닫아 원본 제공자까지 닫는 일이 없도록 소유권 경계를 정하고 테스트한다.
- 본문과 URI 서명: Smithy [`HashSpecification`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-common/common/src/aws/smithy/kotlin/runtime/auth/awssigning/HashSpecification.kt#L6-L50)은 `CalculateFromPayload`, `UnsignedPayload`와 스트리밍 전용 모드를 구분한다. [`Canonicalizer`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-default/common/src/aws/smithy/kotlin/runtime/auth/awssigning/Canonicalizer.kt#L75-L163)는 기본 설정에서 URI를 두 번 인코딩하고 경로를 정규화한다. `UnsignedPayload`는 본문을 읽지 않지만 스트리밍 청크 서명은 일반 `sign()` 호출이 아니라 별도 청크 API와 본문 소스가 필요하다. [`Presigner.kt`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-common/common/src/aws/smithy/kotlin/runtime/auth/awssigning/Presigner.kt#L19-L58)의 `presignRequest()`는 `@InternalApi`이며 고정 Smithy `1.7.9`에 공개 `Presigner` 타입은 없다. 사전 서명은 공개 [`AwsSigner.sign()`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-common/common/src/aws/smithy/kotlin/runtime/auth/awssigning/AwsSigner.kt#L9-L43)과 [`AwsSigningConfig`](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-common/common/src/aws/smithy/kotlin/runtime/auth/awssigning/AwsSigningConfig.kt)를 사용해 `AwsSignatureType.HTTP_REQUEST_VIA_QUERY_PARAMS`, `expiresAfter`, `HashSpecification.UnsignedPayload`와 현재 S3 URI 정규화 설정을 지정한다. 구현 계획에는 공개 API 컴파일 검증과 고정 presign vector를 둔다.
- 로그: [Smithy 로그 가림 설정](https://raw.githubusercontent.com/smithy-lang/smithy-kotlin/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/smithy-client/common/src/aws/smithy/kotlin/runtime/client/LogRedactionConfig.kt#L5-L28)의 기본 민감 헤더 목록은 비어 있으므로 명시 설정이 필요하다. signer의 `logRequest`는 기본 비활성화하고, HTTP 로그 모드만으로 서명기 추적 로그까지 안전하다고 가정하지 않는다.

Smithy Kotlin에는 [AWS signer](https://docs.aws.amazon.com/smithy-kotlin/api/latest/aws-signing-common/aws.smithy.kotlin.runtime.auth.awssigning/-aws-signer/)가 있다. signer는 Ktor 요청 빌더가 아닌 Smithy `HttpRequest`다. 공식 AWS/Smithy 문서에서 Ktor와 Smithy 요청을 연결하는 어댑터는 확인하지 못했다. 따라서 요청 변환기는 이 저장소가 구현·검증해야 하는 경계다. 현재 AWS signer 구현은 [Smithy Kotlin 소스](https://github.com/smithy-lang/smithy-kotlin/blob/6106ef2e27a11e3c4df40058b98599c31924a4ec/runtime/auth/aws-signing-default/common/src/aws/smithy/kotlin/runtime/auth/awssigning/DefaultAwsSigner.kt)에서도 확인했다.

## 선택지와 결정

| 선택지 | 내용 | 결과 |
|---|---|---|
| A. Ktor 통합을 Kotlin SDK로 전면 이전 | 서비스 클라이언트/모델, 공통 기본값, IMDS, SigV4 서명 경계를 AWS Kotlin/Smithy로 이전한다. Ktor S3 REST 동작은 유지한다. | 이슈의 SDK 계열 경계를 충족한다. 모델과 설정 타입은 호환되지 않지만 기능 검증 범위를 명시할 수 있다. **선택** |
| B. 서비스 클라이언트만 이전하고 Java 서명기/S3 예외를 유지 | 작업량을 줄이지만 Ktor에 Java AWS SDK API와 의존성이 남는다. | 이슈의 명시적 요구를 충족하지 않아 기각한다. |
| C. Ktor 서명기와 REST S3 기능을 제거하고 AWS Kotlin `S3Client`로 대체 | 현재 자체 서명 코드를 없애고 SDK S3 클라이언트를 직접 노출한다. | 일반 S3 기능이 일부 대체되더라도 Ktor 클라이언트 플러그인, 임의 서비스 서명, 기존 URL·헤더·암호화 통합의 동작을 보장하지 못해 기각한다. |

선택지 A를 사용한다. 이 결정은 현재 승인된 방향이며, 저장된 명세의 독립 리뷰와 구현 계획 승인을 마치기 전에는 코드 구현을 시작하지 않는다.

## 구성과 책임 경계

### 의존성과 공개 API

- `aws-ktor`에서 `api(project(":bluetape4k-aws-java"))`, Java SDK 서비스 의존성, Java SDK 클라이언트/모델을 공개하는 시그니처를 제거한다.
- `api(project(":bluetape4k-aws-kotlin"))`는 유지한다. 공개 Ktor API가 서비스 클라이언트와 모델을 노출하는 서비스는 대응하는 `aws.sdk.kotlin` 서비스 모듈을 `api`로 선언한다. 서비스 클라이언트나 모델을 공개 API에서 사용하는 모듈만 해당 서비스 artifact를 `api`로 선언하고, 내부 구현에만 쓰는 모듈은 비공개 의존성으로 둔다.
- `cloudwatch`, `cloudwatchlogs`, `eventbridge`, `kinesis`, `s3control`, `s3vectors`, `sesv2`, `sns`, `sqs`, `sts`를 Kotlin SDK 클라이언트/모델로 이관한다. DynamoDB는 이미 Kotlin SDK이므로 현재 동작을 유지한다. 공개 `ImdsKtorOperations`는 `ImdsClient`의 고정된 재시도 동작이 현재 `retries=0` 계약과 직접 대응하지 않으므로, Smithy `HttpClientEngine` 위에 토큰·메타데이터 요청을 명시적으로 구현하는 Kotlin 전용 adapter를 사용한다.
- 서비스 SDK 의존성은 현재 저장소 내부 카탈로그의 정책에 맞춰 `libs.aws.kotlin.*`로 참조한다. 누락된 `s3control`, `s3vectors` 별칭을 추가하고 중복 직접 좌표는 남기지 않는다.
- 서비스 설정은 Kotlin SDK 구성과 Smithy 자격 증명/리전/endpoint 설정을 사용한다. `AwsKtorCore`가 제공하는 공유 기본값과 서비스별 사용자 설정 함수의 적용 순서를 유지하되, Java builder 기반 공개 사용자 설정 함수는 대응하는 Kotlin 구성 사용자 설정 함수로 바뀐다.
- `AwsKtorCore` 공개 기본 설정에서 Java `AwsCredentialsProvider`와 Java 클라이언트 사용자 설정 함수를 제거하고, Kotlin `CredentialsProvider`와 Kotlin 서비스 구성 사용자 설정 함수만 둔다. Ktor 공개 설정에서 두 SDK 계열을 동시에 구성할 수 있는 우회 경로를 남기지 않는다.
- Ktor `HttpClientConfig` customizer는 Ktor 기반 S3 REST client에만 적용한다. 공유 `AwsKtorDefaults.kotlinHttpClient`와 서비스 설정의 `httpClient`는 AWS Kotlin SDK/Smithy `HttpClientEngine`이며 Ktor `HttpClient`와 서로 바꾸어 쓸 수 없다. 생성 서비스 클라이언트는 공유 Smithy 엔진을 사용하고, SDK별 `Config.Builder` customizer와 Ktor HTTP customizer를 별도 타입으로 둔다.
- 서비스 설정은 각 직접 값마다 서비스 명시값 > `AwsKtorCore` 공유 기본값 > SDK 기본값으로 해결해 builder에 한 번 설정한다. 이어 공유 customizer 목록, 서비스 customizer 목록 순서로 호출하며 마지막 customizer가 앞선 직접 값과 customizer 값을 덮어쓸 수 있다. 기존 구현 순서를 유지하며 “명시 설정이 모든 customizer보다 우선”한다고 약속하지 않는다. 주입한 `Operations` 객체는 SDK client 생성을 건너뛰며, 주입한 client는 공유·서비스 설정과 customizer를 적용하지 않는다. 일반 서비스 설정은 환경 변수나 system property를 직접 읽지 않고 애플리케이션이 설정 객체에 전달한다. 단, 현재 Java IMDS가 읽는 endpoint/mode 환경 변수 `AWS_EC2_METADATA_SERVICE_ENDPOINT`, `AWS_EC2_METADATA_SERVICE_ENDPOINT_MODE`, JVM property `aws.ec2MetadataServiceEndpoint`, `aws.ec2MetadataServiceEndpointMode`, profile `ec2_metadata_service_endpoint`, `ec2_metadata_service_endpoint_mode`, timeout 환경 변수 `AWS_METADATA_SERVICE_TIMEOUT`, JVM property `aws.ec2MetadataServiceTimeout`, profile `metadata_service_timeout`의 우선순위와 동작은 adapter가 별도로 보존한다. 각 SDK system setting은 JVM property가 같은 이름의 환경 변수보다 우선한다.
- 서비스 endpoint는 절대 `http`/`https` URL로 변환하며 scheme, authority, port, path prefix를 보존한다. endpoint가 있으면 리전도 필요하다. 서명 요청의 endpoint는 기본적으로 HTTPS다. `AwsKtorDefaults.allowInsecureLocalHttpEndpoint`와 standalone `AwsSigV4Plugin`의 같은 이름 설정은 기본 `false`이며, 활성화해도 host가 정확히 `localhost`(ASCII 대소문자 무시), IPv4 `127.0.0.0/8` literal 또는 IPv6 `::1` literal인 경우만 HTTP를 허용한다. hostname은 DNS 조회하지 않고, 그 밖의 비로컬 HTTP는 opt-in 여부와 무관하게 거부한다. 서비스별/generated config customizer를 모두 적용한 뒤 최종 endpoint에 정책을 적용해 customizer가 검사를 우회하지 못하게 한다. client 설정에서 최종 endpoint를 확인할 수 없으면 요청 전송 경계에서도 검사한다. generic Ktor 서명 요청은 자격 증명 `resolve()` 전에 검사한다. plugin이 endpoint를 확인할 수 없는 호출자 주입 client에는 이 검증이 적용되지 않으며 호출자가 동일한 정책을 책임진다.
- IMDS endpoint에는 별도 전송 정책을 둔다. AWS 문서는 기본 IPv4 `169.254.169.254`와 IPv6 `[fd00:ec2::254]` endpoint로 IMDSv2 토큰을 발급하고 같은 HTTP endpoint의 `X-aws-ec2-metadata-token` header로 메타데이터를 요청한다([AWS IMDS 접근 문서](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html)). 이 작업은 두 AWS 기본 endpoint와 HTTPS endpoint를 허용한다. HTTP loopback endpoint는 `allowInsecureLocalHttpEndpoint` opt-in에서만 허용하며, 그 밖의 HTTP endpoint는 최종 endpoint가 plugin 설정, JVM property, 환경 변수, profile 또는 endpoint mode 중 어디에서 왔는지와 무관하게 첫 token 요청 전에 거부한다. hostname은 DNS 조회하지 않는다. 고정 AWS Kotlin SDK가 IMDS에 `ProxySelector.NoProxy`를 쓰므로 plugin-owned engine도 `ProxySelector.NoProxy`를 강제하고 system/environment proxy를 적용하지 않는다. HTTP token header가 원격 proxy로 평문 전달되지 않도록 하는 이 제한은 기존 사용자 지정 Java HTTP client의 proxy 동작과 다르며 이전 안내에 기록한다. 사용자는 비로컬 HTTP endpoint 거부를 2026-10-20 대화에서 승인했다. 직접 주입한 `ImdsKtorOperations`는 plugin endpoint·proxy 검사를 우회하므로 해당 경로의 endpoint와 전송 신뢰는 호출자 책임이다.
- 클라이언트와 자격 증명 제공자의 소유권은 다음 원칙을 따른다. 주입된 서비스 클라이언트와 `CredentialsProvider`는 호출자가 소유하며 Ktor가 닫지 않는다. 플러그인이 직접 만든 서비스 클라이언트는 애플리케이션 자원으로 한 번 등록하고 종료 시 한 번 닫는다. 플러그인이 직접 만든 제공자는 `CloseableCredentialsProvider`인 경우에만 플러그인 소유 자원으로 닫는다. 호출자가 제공한 `CredentialsProvider`를 플러그인 소유 서비스 클라이언트에 전달할 때는 SDK 클라이언트 종료가 그 제공자에 전파되지 않도록 비소유 위임자를 사용하거나 정확한 close 계약을 먼저 증명한다. SDK 기본 제공자와 서비스 클라이언트 사이에 종료 책임이 겹치지 않도록 실제로 해결된 버전의 `close()` 계약을 구현 계획에서 확인한다. 호출자가 주입한 제공자를 `CachedCredentialsProvider`로 감쌀 경우 wrapper 종료가 원본을 닫지 않도록 비소유 경계를 제공하거나 해당 wrapper를 사용하지 않는다. 공유 `kotlinHttpClient`는 호출자가 소유하며 Ktor 애플리케이션 자원이 닫지 않는다. SDK가 자체 생성한 엔진은 클라이언트 소유권 규칙에 따라 SDK 클라이언트 종료 시 닫는다. 설치 또는 초기화가 실패하면 이미 만든 플러그인 소유 자원만 닫고 호출자 소유 자원은 보존한다.
- `aws-ktor`의 `compileOnly(project(":bluetape4k-aws-exposed"))`는 별도 선택 통합으로 유지할 수 있다. 단, 생성한 POM과 Gradle API/runtime 메타데이터에 이 의존성이나 `aws-java`/Java SDK가 전이되지 않는다는 사실을 검증한다. 해당 경계를 증명하지 못하면 예외로 간주하지 않고 설계·범위를 다시 검토한다.
- `aws-spring-boot`는 `api(project(":bluetape4k-aws-java"))`를 유지하고 주석 처리된 Kotlin 의존 선언을 삭제한다. Spring 코드와 Spring 예제에는 AWS Kotlin 서비스 모듈을 추가하지 않는다.

### 공개 API 이전 표

사용자가 ABI 파괴를 허용했지만 공개 타입 변경은 모호하게 남기지 않는다. 아래는 이행할 공개 계약이다. AWS Kotlin 모델은 현재 동일 서비스의 Java SDK 모델과 같은 이름의 `aws.sdk.kotlin.services.<service>.model` 타입을 사용한다. 사용자 정의 Ktor DTO는 서비스 SDK 모델을 그대로 노출해야 하는 operation parameter/result 외에는 애플리케이션 소유 타입으로 유지한다.

| 현재 공개 항목 | 이행 후 공개 항목 | 결정과 사용 의미 |
|---|---|---|
| `AwsKtorDefaults.javaCredentialsProvider: AwsCredentialsProvider?` | `kotlinCredentialsProvider: CredentialsProvider?` | Smithy `CredentialsProvider`를 사용한다. Java provider 자동 변환이나 별도 Java 어댑터는 제공하지 않는다. |
| `AwsKtorDefaults`의 `*AsyncClientCustomizers`와 `customize(*AsyncClientBuilder)` | `AwsKtorCloudWatchClientCustomizer`, `AwsKtorCloudWatchLogsClientCustomizer`, `AwsKtorEventBridgeClientCustomizer`, `AwsKtorKinesisClientCustomizer`, `AwsKtorS3ControlClientCustomizer`, `AwsKtorS3VectorsClientCustomizer`, `AwsKtorSesV2ClientCustomizer`, `AwsKtorSnsClientCustomizer`, `AwsKtorSqsClientCustomizer`, `AwsKtorStsClientCustomizer` | 각 customizer는 대응 Kotlin SDK `Client.Config.Builder`를 받는다. `AwsKtorDynamoDbClientCustomizer`는 이미 Kotlin SDK builder 기반이므로 유지한다. 서비스별 기본값 설정은 먼저 적용하고, shared customizer 다음 service customizer를 호출한다. 뒤에 실행된 customizer가 앞선 값을 덮어쓸 수 있다. |
| 각 service plugin config의 Java `*AsyncClient?` 및 `AwsCredentialsProvider?` | 대응 AWS Kotlin `*Client?`와 Smithy `CredentialsProvider?` | 주입한 client/provider는 호출자 소유로 유지하고 plugin이 닫지 않는다. 생성한 client의 종료 규칙은 아래 소유권 표를 따른다. 서비스 config의 `endpointOverride`는 `URI?`, 공유 `AwsKtorDefaults.endpointOverride`는 Ktor `Url?`로 유지한다. |
| `EventBridgeKtorOperations`의 suspend 메서드와 `*Async(): CompletableFuture<JavaModel>` 쌍 | Kotlin SDK 모델을 반환하는 suspend 메서드만 | suspend 메서드 이름과 작업별 매개변수 의미를 유지한다. 중복 `CompletableFuture` `*Async` API는 제거한다. Java SDK 모델에 묶인 Java 소스 사용성은 유지 범위가 아니며, 작업 호출은 Kotlin coroutine interop을 통해 마이그레이션한다. 별도 Java 호환 facade는 추가하지 않는다. |
| `SqsConsumerPluginConfig.sqsAsyncClient`, `sqsAsyncClient(customizer)`, `SqsConsumerRuntimeConfig.sqsAsyncClient` | `sqsClient`, `sqsClient(customizer)`, `SqsClient` | consumer polling/ack/nack은 suspend 기반 Kotlin `SqsClient`를 사용한다. 기존 `SqsAsyncClient` 주입 setter를 호출하는 Java fixture는 제거하고 아래 Kotlin 외부 소비자 fixture로 대체한다. |
| SQS `Message`, `MessageAttributeValue`, `SendMessageResponse`를 받는 consumer context/interceptor/converter/send 결과 | 대응 `aws.sdk.kotlin.services.sqs.model` 모델 | `SqsConsumerFailureContext.message`, `afterReceive`, `SqsMessageContext.message`, converter의 raw message target은 Kotlin `Message`다. 기본 `String`/`ByteArray` 변환은 유지하고 `ByteArray`는 현재처럼 message body 문자열의 UTF-8 인코딩 결과다. |
| `S3KtorClient`, `s3KtorClientOf(credentialsProvider=...)`, `AwsKtorDefaults` 기반 S3 factory의 Java `AwsCredentialsProvider` | Smithy `CredentialsProvider` | 명시 provider는 caller-owned다. 인자를 생략하면 S3 factory가 AWS Kotlin default credential chain을 생성해 소유하고 `S3KtorClient.close()` 및 초기화 rollback에서 정리한다. |
| `AwsSigV4PluginConfig`의 Java `AwsCredentialsProvider`와 `AwsV4HttpSigner` | 필수 주입 Smithy `CredentialsProvider`와 Smithy `AwsSigner` | standalone plugin은 별도 resource registry가 없으므로 기본 provider를 생성하지 않는다. 주입 provider는 호출자 소유다. `s3KtorClientOf`가 기본 provider를 만들면 S3 client factory가 함께 소유하고 닫는다. signer는 호출할 때마다 `resolve()`한 값을 사용하고 session token을 header/query signing에 포함한다. |
| `ImdsKtorPluginConfig`의 Java SDK client, enum, HTTP client 및 builder customizer | 아래 IMDS 공개 설정 표 | 기존 Java client/builder 기반 확장점은 제거하거나 명시된 Kotlin 값으로 바꾼다. |
| 루트 `build.gradle.kts`의 Java `SqsConsumerFixture` | AWS Kotlin client/model을 사용하는 Kotlin external-consumer fixture | fixture는 S3 REST, 각 공개 service client/model/customizer, SQS consumer/converter, Smithy SigV4와 IMDS 설정을 소비자 classpath에서 컴파일한다. Java source fixture는 유지하지 않는다. |

#### 서비스별 operation 모델

기존 `Operations`, `Template`, 런타임과 공개 DTO에서 사용하던 AWS generated model은 아래 Kotlin service 모델로 전부 교체한다. 같은 이름의 모델이 없는 경우에는 Kotlin SDK의 대응 request/response 필드를 보존하는 저장소 소유 DTO를 사용하며, 필드 축소를 허용하지 않는다.

| 서비스 | 공개 입력 모델 | 공개 결과/레코드 모델 | 반드시 보존할 필드 의미 |
|---|---|---|---|
| CloudWatch / meter publishing | `DimensionFilter`, `MetricDatum`, `Dimension`, `StandardUnit` | `ListMetricsResponse`, `PutMetricDataResponse` (`putMetricData`/`putMetricDatum` 결과는 response list) | metric 이름/값/unit/timestamp/dimensions, pagination token, response metadata |
| CloudWatch Logs | 고수준 Ktor API의 `CloudWatchLogEvent(message: String, timestamp: Long)`; 내부 전송은 Kotlin `InputLogEvent`; `CreateLogGroupRequest`, `CreateLogStreamRequest`, `PutLogEventsRequest`, `DescribeLogGroupsRequest`, `DescribeLogStreamsRequest`에 대응하는 입력 | `CreateLogGroupResponse`, `CreateLogStreamResponse`, `PutLogEventsResponse`, `DescribeLogGroupsResponse`, `DescribeLogStreamsResponse` | sequence token, rejected event/entity, pagination과 response metadata |
| EventBridge | `PutEventsRequestEntry`, `Target`, `RuleState`와 기존 operation 매개변수 | `CreateEventBusResponse`, `DeleteEventBusResponse`, `PutRuleResponse`, `DeleteRuleResponse`, `PutTargetsResponse`, `RemoveTargetsResponse`, `ListRulesResponse`, `ListTargetsByRuleResponse`, `PutEventsResponse` | failed entry count/index/code/message, target optional fields, next token과 metadata |
| Kinesis | `KinesisPutRecordRequest.data: ByteArray`, `PutRecordsRequestEntry`, `KinesisShardIteratorRequest`의 Kotlin `ShardIteratorType` | `CreateStreamResponse`, `DeleteStreamResponse`, `DescribeStreamResponse`, `PutRecordResponse`, `PutRecordsResponse`, `GetShardIteratorResponse`, `GetRecordsResponse`, `Record` | sequence number, partition key, arrival timestamp, encryption type, per-record error/index, iterator unknown variant |
| S3 Access Grants | `GetDataAccessRequest`, `ListAccessGrantsInstancesRequest`, `ListAccessGrantsLocationsRequest`, `ListAccessGrantsRequest`, `ListCallerAccessGrantsRequest` | 같은 이름의 `GetDataAccessResponse`, `ListAccessGrantsInstancesResponse`, `ListAccessGrantsLocationsResponse`, `ListAccessGrantsResponse`, `ListCallerAccessGrantsResponse` | pagination, grant/instance/location, scope/permission, temporary credentials, unknown enum/string 값 |
| S3 Vectors | 현재 `S3VectorsOperations`에 노출된 각 request의 동일 이름 Kotlin `aws.sdk.kotlin.services.s3vectors.model` 타입 | 각 현재 operation의 동일 이름 Kotlin response | distance, vector data/key/metadata, pagination 및 모든 서비스 response 필드; `bluetape4k-aws-java`의 wrapper를 공개 타입으로 재사용하지 않음 |
| SES v2 | `SendEmailRequest`와 저장소 소유 `SesEmailRequest`, `SesTemplateEmailRequest`, `SesRawEmailRequest`, attachment DTO; attachment enum은 SDK 타입 대신 repository enum | `SendEmailResponse` | message ID와 metadata, raw bytes 전체, attachment bytes defensive copy, `AttachmentContentDisposition`/`AttachmentContentTransferEncoding`의 모든 variant |
| SNS | 저장소 소유 `SnsMessageAttribute(dataType, stringValue, binaryValue, stringListValues, binaryListValues)` | publish/confirm에 대응하는 Kotlin response | Java 모델의 모든 string/binary/list 속성, binary byte 방어 복사, message ID/sequence/subscription ARN; SMS 자동 생성 속성이 같은 키를 덮어쓰는 순서 |
| SQS | Kotlin `MessageAttributeValue`와 `Message` generated model | Kotlin `SendMessageResponse` 등 operation별 response | message ID, receipt handle, body, 모든 system/message attributes, MD5와 FIFO 필드 |
| STS | 저장소 소유 `StsAssumeRoleRequest`, `StsSessionTokenRequest` | `GetCallerIdentityResponse`, `AssumeRoleResponse`, `GetSessionTokenResponse` | account/ARN/user ID, credentials, assumed-role user, packed policy size, source identity; secret은 `toString`/로그에서 제외 |
| DynamoDB | 현재 Kotlin SDK request/model | 현재 Kotlin SDK response/model | 기존 동작 유지 |

`KinesisPutRecordRequest.data`는 현재 `SdkBytes`가 보장하던 불변 사용 의미를 유지하도록 생성 시 입력 배열을 복사하고 읽을 때 방어 복사본을 반환한다. 내부 mapping은 소유 배열을 재사용하여 추가 전체 복사를 피한다. `KinesisShardIteratorRequest.type`은 Kotlin SDK의 sealed `ShardIteratorType`으로 바꾸고 알려진 값 5개와 `SdkUnknown(raw)`를 모두 보존한다. `SnsMessageAttribute`의 `binaryValue`와 `binaryListValues`는 생성 시/읽을 때 복사한다. SQS generated message model의 binary attribute를 새 Kotlin request에 옮길 때도 배열을 복사한다. SDK 생성 모델의 나머지 request/response collection은 호출자가 전달·소유하는 값으로 취급하며 wrapper가 이를 별도 장기 보관하거나 수정하지 않는다. AWS Kotlin generated enum/sealed model의 알 수 없는 원시 값은 `SdkUnknown(raw)` 또는 대응 SDK의 unknown variant로 보존한다.

#### IMDS 공개 설정 이전 표

| 현재 `ImdsKtorPluginConfig` 표면 | 이행 계약 | 결정 |
|---|---|---|
| `enabled` | 동일 이름과 기본값 | 유지 |
| `imdsOperations: ImdsKtorOperations?` | 동일한 Kotlin-only operation injection | 유지. 주입된 operation은 호출자가 소유하며 endpoint/redirect 정책의 적용은 호출자 책임이다. |
| `ec2MetadataAsyncClient: Ec2MetadataAsyncClient?` | 대체 property 없음 | 원시 Java SDK client injection을 제거한다. 기존 `imdsOperations: ImdsKtorOperations?` 주입점을 재사용하며 새 중복 operation property는 만들지 않는다. |
| `endpoint: URI?` | `endpoint: URI?` | 유지. absolute HTTP/HTTPS, endpoint/mode 우선순위, local HTTP gate를 plugin이 적용한다. |
| `endpointMode: EndpointMode? = IPV4` | `aws.sdk.kotlin.runtime.config.imds.EndpointMode? = EndpointMode.IPv4` | AWS Kotlin SDK enum으로 교체한다. plugin `endpoint`가 가장 우선하고, 없으면 Java SDK endpoint system setting과 active profile이 우선하며, mode는 기본 주소를 결정한다. plugin의 기본 `EndpointMode.IPv4`는 SDK mode property/env/profile/default보다 먼저 적용되므로 해당 설정은 `endpointMode=null`일 때만 주소 선택에 영향을 준다. profile은 `aws.profile`/`AWS_PROFILE`과 표준 config/credentials file 경로·section 규칙을 좁은 repository-owned resolver로 읽는다. |
| `tokenTtl: Duration` | 동일 값과 기본값 | 유지 |
| `requestTimeout: Duration` | 동일 값과 기본값 | 유지. token, metadata, retry delay, parsing을 포함한 작업 전체 제한 시간이다. |
| `retries: Int` 및 Java `Ec2MetadataRetryPolicy` customizer를 통한 설정 | `retries: Int` | 유지하되 Java retry policy/customizer는 제거한다. 최초 요청 뒤 추가 횟수, retryable 응답/예외, backoff는 동작 계약에 명시한다. |
| `httpClient: SdkAsyncHttpClient?` | 대체 transport/proxy property 없음 | 임의 transport/engine injection을 제거한다. plugin 소유 전용 Smithy OkHttp engine을 생성하고 `ProxySelector.NoProxy`, redirect off, 숨은 connection retry off를 강제한다. JVM/profile의 connect/read timeout은 plugin engine에 적용하고 `requestTimeout`은 전체 operation 상한이다. 기존 custom HTTP client와 system/environment proxy 설정은 IMDS에 적용되지 않는다. |
| `client(ImdsKtorClientCustomizer)` / Java builder customizer | 명시 설정 속성만 | 제거한다. builder customizer는 endpoint 검사, proxy 제한, redirect 차단, retry/timeout 동작을 덮어쓸 수 있다. 이행하는 설정은 endpoint, endpoint mode, token TTL, 작업 timeout, retry count, local HTTP opt-in이다. |
| 신규 `allowInsecureLocalHttpEndpoint: Boolean = false` | `ImdsKtorPluginConfig` 전용 opt-in | 이 property만 IMDS HTTP 예외를 결정한다. `AwsKtorDefaults`나 standalone signer 설정을 상속하지 않는다. 기본 AWS IMDS IPv4/IPv6 endpoint와 HTTPS는 허용하고, HTTP loopback만 명시 opt-in할 수 있다. |

plugin 소유 IMDS engine은 `connectTimeout`과 `socketReadTimeout`에 해석된 Java SDK IMDS timeout을 적용한다. endpoint 자체는 plugin의 `endpoint` > JVM property `aws.ec2MetadataServiceEndpoint` > 환경 변수 `AWS_EC2_METADATA_SERVICE_ENDPOINT` > active profile `ec2_metadata_service_endpoint` > mode로 계산한 주소 순이다. plugin의 `endpointMode`(기본 `EndpointMode.IPv4`)가 지정되면 SDK endpoint-mode property/env/profile/default보다 우선해 기본 주소를 정한다. `endpointMode=null`이면 JVM property `aws.ec2MetadataServiceEndpointMode` > 환경 변수 `AWS_EC2_METADATA_SERVICE_ENDPOINT_MODE` > active profile `ec2_metadata_service_endpoint_mode` > SDK 기본값 순이다. endpoint가 있으면 mode를 사용하지 않는다. timeout precedence는 JVM property `aws.ec2MetadataServiceTimeout` → 환경 변수 `AWS_METADATA_SERVICE_TIMEOUT` → active profile `metadata_service_timeout` → Java SDK 기본값이다. active profile/file selection과 key resolution은 위의 `ImdsProfileResolver` 계약을 따르고, profile source precedence·section parsing·timeout 숫자 형식·잘못된 timeout 예외를 결정적으로 테스트한다. `requestTimeout`은 token 요청, metadata 요청, retry delay와 결과 변환을 포함한 전체 operation 상한이다. IMDS engine은 항상 `ProxySelector.NoProxy`를 사용하고 공유 `AwsKtorDefaults.kotlinHttpClient`를 전달받지 않는다.

IMDS plugin은 `ProxySelector.NoProxy`, redirect off, engine 내부 connection retry off인 Smithy OkHttp engine을 소유한다. token 요청과 metadata 요청 모두 3xx를 terminal 실패로 반환하고 후속 URL을 요청하지 않는다. `Location`이 다른 authority를 가리켜도 같으며 token header를 전달하지 않는다. plugin은 임의 `HttpClientEngine`/`SdkAsyncHttpClient` injection이나 proxy configuration을 받지 않는다. 직접 주입한 `ImdsKtorOperations`에는 plugin이 endpoint·proxy·redirect 정책을 강제할 수 없으므로 호출자가 동일한 보호를 구현해야 한다.

### 서비스별 공개 SDK 매핑

각 `Operations`, `Template`, `PluginConfig`의 서비스 client와 공개 요청/응답 모델은 아래 AWS Kotlin SDK 모듈로 옮긴다. 공개 시그니처가 생성 SDK 타입을 노출하므로 표의 서비스 artifact는 `api` 범위로 선언한다. 네트워크를 수행하는 `Operations` 메서드는 suspend 함수로 통일하고, Java `CompletableFuture`를 반환하는 `*Async` 중복 메서드는 제거한다. 사용자 정의 Ktor request/consumer DTO는 이미 Ktor 동작을 표현하는 경우 유지하되 내부 변환은 Kotlin SDK 모델을 사용한다. Kinesis의 `Flow` API는 cold/cancellable flow로 유지한다.

| 현재 Ktor 통합 | 공개 client/model의 대상 | AWS Kotlin SDK artifact | 범위 |
|---|---|---|---|
| `cloudwatch`와 meter publishing | `CloudWatchClient`, CloudWatch model | `cloudwatch` | `api` |
| `cloudwatchlogs` | `CloudWatchLogsClient`, CloudWatch Logs model | `cloudwatchlogs` | `api` |
| `eventbridge` | `EventBridgeClient`, EventBridge model | `eventbridge` | `api` |
| `kinesis` | `KinesisClient`, Kinesis model | `kinesis` | `api` |
| `s3/accessgrants` | `S3ControlClient`, S3 Control model | `s3control` — catalog alias 추가 | `api` |
| `s3vectors` | `S3VectorsClient`, S3 Vectors model | `s3vectors` — catalog alias 추가 | `api` |
| `ses` | `SesV2Client`, SES v2 model | `sesv2` | `api` |
| `sns` | `SnsClient`, SNS model | `sns` | `api` |
| `sqs` | `SqsClient`, SQS model | `sqs` | `api` |
| `sts` | `StsClient`, STS model | `sts` | `api` |
| `dynamodb` | 기존 `DynamoDbClient`, DynamoDB model | `dynamodb` | `api` |

서비스 동작은 아래에 열거한 의도적 이행 변경을 제외하고 유지한다. `Operations`의 suspend 메서드와 기존 서비스 동작을 유지하되, EventBridge `CompletableFuture` `*Async` 메서드는 제거한다. API 이전 표의 customizer, client/provider property, IMDS transport, Java SQS fixture 행은 이름·타입을 교체하거나 제거하는 예외다. 각 service config의 `endpointOverride: URI?`와 공유 `AwsKtorDefaults.endpointOverride: Url?`는 타입을 그대로 유지한다. Java service model은 같은 작업의 AWS Kotlin request/response model로 교체하며, nullable 값·enum·binary stream을 변환해야 하는 경우 해당 메서드의 매핑 규칙을 implementation plan에 고정한다. SNS HTTP notification parser처럼 AWS SDK service model을 사용하지 않는 HTTP wire model은 그대로 둔다.

현재 공개 Ktor DTO/설정 중 Kinesis 요청·값 DTO, `SqsPollBackoff`, SQS failure strategy·observation DTO, `SqsConsumerFailureContext`, `SqsConsumerRuntimeConfig`에는 `Serializable` marker가 있고 고정 `serialVersionUID`도 선언되어 있다. 해당 marker와 UID는 유지한다. 값 DTO와 `SqsConsumerFailureContext`처럼 SDK model을 담는 타입은 AWS generated model을 serial form에 직접 넣지 않고 저장소 소유 표현으로 변환한다. 구현 전 characterization으로 현재 성공하는 입력을 고정하고 그 값을 round-trip한다. 단, AWS Java 2.54.12의 `SdkBytes`는 `Serializable`을 구현하지만 backing `bytes`는 직렬화되지 않는 `BytesWrapper`에 있어 `KinesisPutRecordRequest` 왕복 시 payload가 빈 배열로 바뀐다. migration은 이 손실을 보존하지 않고 저장소 소유 바이트 표현으로 non-empty payload round-trip과 방어 복사를 검증한다. `SqsLinearFailureVisibilityStrategy`의 사용자 주입 `Random` 상태와 `SqsConsumerRuntimeConfig`의 handler/interceptor/observer, converter, dispatcher 등 호출자 객체를 포함한 임의 객체 그래프는 직렬화 동작을 보장하지 않는다. 이전 Java serialized bytes와의 호환성도 보장하지 않으며 영향 DTO와 migration을 `CHANGELOG.md`에 기록한다. ABI 호환을 허용했다는 사실은 이 명시적인 serialization 정책을 대체하지 않는다.

### 자원 소유권 표

| 자원 | 생성·주입 | 종료 책임 |
|---|---|---|
| plugin 생성 AWS Kotlin service client | application service plugin | Ktor application resource registry에 한 번 등록하고 종료 시 한 번 닫음 |
| 호출자가 주입한 service client 또는 `Operations` | 호출자 | plugin은 닫지 않음; `Operations` 주입 시 client 생성도 생략 |
| `AwsKtorDefaults.kotlinHttpClient` 등 공유 Smithy engine | 호출자 | service client를 모두 종료한 뒤 호출자가 한 번 닫음; 각 client 종료가 공유 engine을 닫지 않도록 비소유 wrapper를 검증 |
| SDK가 내부 생성한 engine | AWS Kotlin SDK client | client 종료에 따라 SDK가 닫음; 실제 해결 버전의 소유권을 implementation plan에서 확인 |
| 호출자가 주입한 credentials provider | 호출자 | plugin/client가 닫지 않음; SDK 종료에 close가 전파되면 비소유 wrapper 사용 |
| plugin이 생성한 closeable credentials provider | plugin | application resource registry에 한 번 등록하고 한 번 닫음 |
| standalone `AwsSigV4Plugin`의 credentials provider | 호출자가 필수 주입 | caller-owned; plugin은 닫지 않고 application registry에 등록하지 않음 |
| `s3KtorClientOf`가 만든 Ktor `HttpClient` | S3 client factory | factory가 소유하며 `S3KtorClient.close()`에서 한 번 닫음 |
| `s3KtorClientOf`가 만든 기본 credentials provider | S3 client factory | factory가 `HttpClient`와 함께 소유하고 종료 시 한 번 닫음; 초기화 실패 시 rollback에서 닫음 |
| S3 factory에 주입한 credentials provider | 호출자 | factory는 닫지 않음 |

초기화가 실패하면 이미 만들어진 plugin 소유 자원만 역순으로 닫는다. 초기화 오류는 원래 실패를 보존하고 cleanup 오류를 suppressed exception으로 남긴다. 호출자 소유 client, provider, engine은 실패 경로에서도 유지한다.

### 서비스 동작

- 서비스별 `Operations`, `Template`, `PluginConfig`, `Runtime`, Ktor application accessor를 기존 책임과 파일 경계에 맞춰 Kotlin SDK 클라이언트와 모델을 사용하도록 이관한다. 공개 SDK 타입 교체는 ABI/소스 호환성 변경으로 문서화한다.
- AWS Kotlin suspend API를 직접 호출한다. Java `CompletableFuture.await()`와 동기 대기를 새 Ktor 구현으로 옮기지 않는다. 취소는 현재 코루틴 취소 계약을 따른다.
- application service plugin이 만든 클라이언트는 Ktor 애플리케이션 자원 등록부에 한 번 등록하고 종료 시 한 번 닫는다. 호출자가 주입한 클라이언트/`Operations` 객체는 Ktor 실행 환경이 닫지 않는다. standalone `AwsSigV4Plugin`은 필수 주입된 provider를 빌려 쓰고 닫거나 application registry에 등록하지 않는다. `s3KtorClientOf`가 만든 기본 provider와 내부 `HttpClient`는 `S3KtorClient`가 소유하며 각각 한 번 닫는다. 모든 생성/설치 실패 경로는 이미 생성한 plugin/factory 소유 자원만 역순으로 정리한다.
- SQS 소비자는 기존 폴링, 가시성, 수동 승인/거부(ack/nack), 재시도, 메시지 변환, 관찰자 콜백, 지표와 종료 동작을 유지한다. 특히 코루틴 수와 `maxMessages`를 곱한 처리기 동시성 제한, poller가 한 번에 최대 `maxMessages`개를 받는 `ReceiveMessage` 배치 요청, `waitTimeSeconds` 장기 폴링을 보존한다. 수신 실패는 `pollBackoff`에 따라 재시도하며 SDK 내부 재시도와는 별도 계층으로 둔다. 처리기 실패는 설정된 실패 처리 전략과 가시성 변경을 사용하며, 수신 반복문이 같은 메시지를 임의로 재처리하지 않는다. `stop()`은 poller를 취소하고 join한 뒤 `shutdownTimeout`까지 처리기 완료를 기다린다. 종료 제한 시간 안에 끝나지 않은 처리 작업과 가시성 연장 신호에는 취소를 요청한 뒤 기존 순서대로 플러그인 소유 클라이언트를 닫는다. 취소 중인 ack/nack/visibility 요청의 원격 결과는 확정되지 않을 수 있고 SQS가 메시지를 다시 전달할 수 있다. 정확히 한 번 처리는 보장하지 않는다.
- IMDS adapter는 설치 시점에 요청을 보내지 않으며 `ImdsKtorOperations.get/getList`, 경로 정규화, endpoint 및 IPv4/IPv6 mode, `tokenTtl`, IMDSv2 token 캐시·만료 시 갱신, 401 실패와 캐시 유지, 취소 전파를 보존한다. 만료 전에 토큰을 갱신하거나 401에서 재시도·캐시 무효화를 하지 않는다. `retries=0`은 최초 시도 한 번이며 양수 `N`은 token/metadata를 포함한 operation 전체를 최초 시도 뒤 최대 `N`회 더 시도한다. 5xx 응답과 `HttpException.sdkErrorMetadata.isRetryable == true`인 예외는 재시도한다. 고정 Smithy OkHttp engine은 모든 `IOException`(connect/read/socket timeout과 TLS handshake 포함)을 retryable metadata가 있는 `HttpException`으로 매핑한다. `CONNECT_TIMEOUT`과 `TLS_NEGOTIATION_TIMEOUT`은 metadata 규칙상 retryable이고, 나머지는 공개 `sdkErrorMetadata.isRetryable` 값으로 판정한다. 3xx, 401을 포함한 기타 4xx, 그 밖의 status, metadata가 retryable이 아닌 예외는 terminal이다. cancellation과 `requestTimeout`에 따른 취소는 재시도하지 않고 전파한다. 전용 engine의 내부 connection retry와 redirect는 비활성화해 추가 wire request를 막는다. full-jitter delay upper bound는 200ms, 400ms, 800ms, 1600ms, 3200ms, 6400ms, 12800ms, 이후 20초이며 실제 delay는 1ms부터 각 upper bound까지다. 전체 `withTimeout(requestTimeout)`은 token 획득, metadata 요청, 모든 delay와 결과 변환을 제한한다. 명시 endpoint, endpoint/mode JVM property/environment/profile/default 우선순위와 connect/read timeout(`aws.ec2MetadataServiceTimeout` / `AWS_METADATA_SERVICE_TIMEOUT` / `metadata_service_timeout`)을 유지한다. plugin-owned engine은 `ProxySelector.NoProxy`를 강제하고 임의 transport/proxy injection을 제공하지 않는다. plugin이 최종 HTTP endpoint를 첫 token 요청 전에 검사한다. plugin 소유 engine만 한 번 닫는다. `SdkHttpClient.call(HttpRequestBuilder)`는 공개 API에 두고 `HttpCall.complete()`의 `@InternalApi` 사용은 한 내부 함수로 격리해 모든 완료·오류 경로 cleanup을 검증한다. 이 adapter는 Kotlin SDK `ImdsClient`의 구현되지 않은 `maxRetries` 설정에 의존하지 않는다.
- `AwsSigV4Plugin`은 서명 직전에 매 요청마다 자격 증명 제공자의 `resolve()`를 호출해 현재 access key(접근 키), secret key(비밀 키), session token(세션 토큰)을 서명기에 전달한다. 제공자가 회전·갱신한 자격 증명을 어댑터가 요청 사이에 보관하지 않고, 오류와 코루틴 취소를 전파한다. standalone plugin은 provider를 필수 주입받으며 호출자 소유이므로 닫지 않는다. `s3KtorClientOf`가 기본 provider를 생성한 경우 S3 factory가 client와 함께 한 번 닫는다. 쿼리 서명과 사전 서명에도 session token을 포함한다.
- 서명 어댑터는 자격 증명을 resolve하기 전에 최종 endpoint의 HTTPS/local HTTP 정책을 검사한다. 서명용 정규 URI와 실제 전송 요청을 동일하게 유지한다. 원시 인코딩 경로, URI authority, `%2F`, `%20`, 중복 쿼리 키, 빈 쿼리 값과 중복 헤더 값이 서명기와 실제 요청 사이에서 변형되지 않아야 한다. 서명기가 URL을 정규화하거나 변경하면 서명 결과의 URI와 authority를 실제 요청에 적용하거나, 표현할 수 없는 요청을 전송 전에 거부한다.
- `AwsSigV4Plugin`과 `S3KtorClient`는 Smithy 요청 서명을 위해 Ktor URL, HTTP method, headers와 payload를 어댑터에서 변환한다. 서비스명, 리전, 서명 위치, payload 서명과 재생할 수 없는 본문의 거부 조건을 유지한다. payload 서명을 비활성화하면 스트리밍 `OutgoingContent`를 바이트 배열로 버퍼링하지 않고 지연된 본문으로 전달하며 Smithy `UnsignedPayload`와 S3 `x-amz-content-sha256` 값을 정확히 설정한다. 현재 payload 서명은 재생 가능한 `ByteArrayContent`만 지원한다. 재생할 수 없는 본문은 거부하며 스트리밍 청크 서명을 지원한다고 간주하지 않는다. 서명기와 전송 계층이 본문을 중복 소비하거나 서명 입력과 실제 전송 본문이 달라져서는 안 되며, 대용량 업로드에서 본문 전체를 복사하지 않아야 한다.
- S3 사전 서명 URL은 쿼리 서명, 만료 시간 검증, `UNSIGNED-PAYLOAD`, 경로 정규화·인코딩 설정과 고정 서명 시각 동작을 유지한다. 서명된 헤더, session token과 정규화된 쿼리 결과를 반환 URL에 정확히 적용한다. URL 생성에도 동일한 HTTPS/local HTTP 정책을 적용해 비로컬 HTTP URL에 서명 결과를 만들지 않는다.
- 서명기 진단은 기본적으로 서명용 요청이나 민감 요청 정보를 추적 로그에 기록하지 않는다. Authorization, session token, signature가 포함된 사전 서명 쿼리, 본문과 비밀 값을 로그에 남기지 않으며 현재 S3 로그 가림 테스트를 보존한다.
- Ktor 테스트, 다섯 Ktor 예제(`aws-ktor-dynamodb-examples`, `aws-ktor-exposed-examples`, `aws-ktor-s3-examples`, `aws-ktor-service-coverage-examples`, `aws-ktor-sqs-examples`)와 소비자 fixture를 Kotlin SDK 타입으로 변경한다. 각 예제의 Gradle 의존성, source/test, 존재하는 영문·한국어 README를 검토한다. 외부 fixture는 각 공개 service client/model/customizer, S3 REST, SQS consumer/converter, SigV4와 IMDS를 Kotlin 소비자 classpath에서 컴파일한다.
- Kinesis `recordFlow`의 `ExpiredIteratorException`은 마지막 관측 sequence number를 `AfterSequenceNumber`로 재획득하고 `maxIteratorRetries` 상한을 지킨다. 최초 위치가 `Latest`이고 아직 record가 없다면 임의의 iterator 복구를 하지 않는다. throttle 재시도는 `maxThrottleRetries`, `initialThrottleBackoff`, `maxThrottleBackoff`, `jitterRatio` 경계를 유지하며 성공 후 연속 실패 수를 초기화한다. empty poll과 non-empty poll delay, cold flow와 취소 전파도 유지한다.
- CloudWatch Logs `flush()`는 timestamp 정렬과 chunk 전송을 유지한다. 어떤 chunk가 실패하거나 취소되면 flush 시작 때 drain한 전체 event 목록을 기존과 같이 buffer 앞에 복원한다. 앞 chunk가 이미 성공한 경우 중복 재전송 가능성을 명시하고, 로그 손실 대신 적어도 한 번 전달을 선택한다. `stop()`은 periodic flush를 중지하고 `shutdownFlushTimeout` 안에 한 번 최종 flush를 시도하며, timeout 정책·남은 buffer의 dropped count 보고·owned client 종료 순서를 유지한다.

## 동작 계약과 실패 모드

ABI 호환성은 요구하지 않지만 기존 기능 동작은 보존한다. 구현 검토는 다음 실패를 중심으로 한다.

1. **서명 입력 변환 불일치:** URI 경로·쿼리, host, 중복 헤더 또는 payload 바이트가 달라지면 AWS 서명이 실패하거나 다른 요청이 전송될 수 있다. Ktor 요청 단위 테스트와 Floci S3 통합 테스트에서 경계 값을 검증한다.
   SDK 서명기 결과와 실제 전송 요청이 동일한지 AWS SigV4 기준 벡터와 실제 전송 기록으로 확인한다. session token, 퍼센트 인코딩 경로, 중복·빈 쿼리 값과 헤더를 포함한다.
2. **클라이언트 소유권·종료 불일치:** 클라이언트 종료가 누락되거나 주입된 클라이언트를 닫으면 연결 풀 누수 또는 사용자 자원 손실이 생긴다. 플러그인이 만든 클라이언트는 정확히 한 번 닫고 주입된 클라이언트는 유지하는 수명 주기 테스트를 둔다.
3. **SQS 취소·재시도 의미 변화:** suspend 호출로 전환하면 코루틴 취소가 폴링이나 가시성 변경 요청의 완료를 보장하지 못할 수 있다. 대기 중 취소, 재시도, ack/nack과 종료 테스트를 기존 시나리오에 맞춰 둔다.
   기존 최대 동시 처리량, poller마다 한 번에 최대 `maxMessages`개를 받는 동작과 장기 폴링 설정을 보존하고, 부하 테스트에서 동시 처리기 상한과 batch 기반 수신 요청 수를 검증한다. `pollBackoff`, SDK 재시도, 처리기 실패 정책, 가시성/재전달을 나누어 테스트한다. 종료 제한 시간 뒤에는 취소 요청과 클라이언트 종료 순서, 처리 중인 원격 요청의 불확정 결과와 재전달을 검증한다.
4. **서비스 클라이언트의 엔진 중복 생성 또는 조기 종료:** Kotlin SDK 클라이언트가 공유 엔진을 받지 않거나 클라이언트와 엔진의 종료 순서가 뒤섞이면 서비스별 연결 풀이 중복되거나 사용 중인 클라이언트의 연결이 끊길 수 있다. 설정별 엔진 식별자와 종료 순서를 테스트한다.
5. **IMDS 설정·재시도 의미 변화:** 현재 기본값은 재시도 없음이며 작업별 timeout은 token 요청부터 응답 파싱까지 전체 작업을 제한한다. 고정 Smithy `1.7.9` OkHttp engine의 모든 `IOException`은 retryable metadata가 설정된 `HttpException`으로 매핑된다. 5xx와 `sdkErrorMetadata.isRetryable`이 참인 transport만 재시도하고, 3xx·401/기타 4xx·terminal exception은 재시도하지 않는다. 취소/작업 timeout은 재시도하지 않는다. Java `RetryMode.STANDARD`와 같은 full-jitter cap은 200ms, 400ms, 800ms, 1600ms, 3200ms, 6400ms, 12800ms, 이후 20초다. `retryOnConnectionFailure=false`와 redirect off로 engine 내부 추가 요청을 막는다. plugin IMDS proxy는 `ProxySelector.NoProxy`로 고정되어 기존 Java client의 proxy 설정을 따르지 않는다. `HttpCall.complete()`는 `@InternalApi`이므로 resolved Smithy 버전에서 모든 경로 cleanup을 검증한다.
6. **IMDS 토큰 endpoint 노출과 redirect 우회:** HTTP remote endpoint override로 token 요청을 보내면 token header가 암호화 없이 전송될 수 있고 3xx follow-up은 허용 endpoint 검사를 우회할 수 있다. AWS 기본 endpoint, HTTPS, opt-in한 loopback HTTP만 허용한다. 그 밖의 HTTP endpoint는 첫 token 요청 전에 거부한다. token과 metadata의 모든 3xx는 terminal이고 `Location`으로 후속 요청하지 않는다. plugin engine은 proxy를 쓰지 않으며 직접 주입된 `ImdsKtorOperations` 내부에는 endpoint·proxy·redirect 정책을 강제할 수 없어 호출자가 보호 책임을 진다. 비로컬 HTTP 제한은 사용자가 2026-10-20에 승인했다.
7. **자격 증명 갱신·session token 누락:** 이전 `resolve()` 결과를 재사용하거나 session token을 서명에서 빠뜨리면 임시 자격 증명, 만료 처리 또는 사전 서명 URL 요청이 실패한다. 매 요청의 `resolve()`, 제공자 교체, 만료 갱신, 헤더·쿼리 session token과 제공자 종료 소유권을 검증한다.
8. **민감 요청 데이터 로깅:** 서명기 추적 로그 설정이 정규화된 query, Authorization 또는 body를 기록할 수 있다. 기본 비활성화와 민감정보 가림 테스트를 유지한다.
9. **서명 HTTP endpoint 노출:** endpoint override 또는 generated config customizer가 비로컬 `http://`를 설정하면 `Authorization`과 session token이 평문으로 전송될 수 있다. HTTPS 기본값, 정확한 loopback literal만 허용하는 opt-in, customizer 적용 뒤 최종 endpoint 검사, credentials resolve 전 거부, DNS 조회 없이 `localhost`/loopback 주소 허용과 원격 HTTP 거부 테스트를 유지한다.
10. **SQS 재시도·종료 순서 변화:** polling retry, SDK retry, handler 실패/재전달이 섞이면 중복 작업이나 영구 지연이 발생할 수 있다. `pollBackoff`와 SDK retry를 따로 검증한다. `stop()`은 poller cancel/join 후 `shutdownTimeout`까지 handler를 기다리고, 만료되면 남은 handler와 heartbeat에 취소를 요청한 뒤 현재 계약대로 소유 client를 닫는다. timeout 뒤 handler 취소 완료를 무기한 기다리는 장벽은 두지 않으며, 진행 중인 ack/nack 결과는 확정되지 않고 메시지가 재전달될 수 있음을 명시한다.
11. **서비스 모델 의미 손실:** nullable 값, enum, 바이트 본문, 응답 식별자가 Kotlin 모델에서 달라질 수 있다. 서비스별 매핑/단위 테스트와 현재 가능한 Floci 에뮬레이터 테스트를 실행한다.
12. **Java SDK 의존성 유출:** Ktor 공개 메타데이터, 컴파일 API, 예제 또는 fixture에 Java SDK가 남으면 경계가 완성되지 않는다. 소스 검색, 의존성 보고서, 생성한 POM 및 Gradle module metadata를 함께 검사한다.
13. **catalog 별칭 또는 런타임 의존성 누락:** 빌드가 성공해도 외부 Ktor 소비자가 필요한 Kotlin 서비스 모듈을 받지 못할 수 있다. 외부 소비자 fixture와 예제 컴파일로 공개 classpath를 증명한다.

## 인수 조건

1. `aws-ktor/src`, `src/consumerFixture`, 다섯 Ktor 예제의 소스·테스트·Gradle 파일 및 존재하는 README에서 `software.amazon.awssdk` 타입과 Java SDK import 또는 `libs.aws2.*` direct dependency alias를 제거한다. Java `SqsConsumerFixture`는 Kotlin external-consumer fixture로 교체한다. 각 예제의 main `compileClasspath`/`runtimeClasspath`와 fixture의 consumer compile/runtime classpath dependency report에 `software.amazon.awssdk:*` 또는 `bluetape4k-aws-java`가 없어야 한다.
2. 서비스별 공개 client/model은 정한 AWS Kotlin artifact를 `api`로 공개한다. `aws-credentials`, `aws-signing-common`, KMP root `http-client`는 Smithy `1.7.9` public types 때문에 `api`; `aws-signing-default`와 KMP root `http-client-engine-okhttp`은 내부 구현이므로 `implementation`이다. JVM variant 선택은 Gradle dependency report와 module metadata로 확인한다. Ktor `HttpClientConfig`, Smithy `HttpClientEngine`, service `Config.Builder` customizer는 별도 타입이며 dependency report, POM, Gradle module metadata와 consumer fixture가 이를 증명한다. `DefaultAwsSigner`를 쓰기 위해 `aws-signing-default` catalog alias를 추가하고, 그 artifact가 `api` metadata로 노출되지 않는지 확인한다.
3. 발행 `aws-ktor` POM/Gradle metadata에는 `bluetape4k-aws-java`나 `software.amazon.awssdk:*`가 없다. `aws-spring-boot`는 `bluetape4k-aws-java`만 유지하고 AWS Kotlin 프로젝트·서비스 의존성이나 source reference를 갖지 않는다.
4. resource ownership 표를 따른다. 검증은 application service plugin 생성 자원 등록, 주입 자원 미종료, standalone `AwsSigV4Plugin`의 필수 caller-owned provider, S3 factory가 만든 `HttpClient`/기본 provider의 정확히 한 번 종료, 초기화 rollback과 종료 순서를 포함한다.
5. AWS service builder 순서는 SDK defaults → shared settings → service explicit settings → shared customizers → service customizers다. shared/service customizer는 앞선 explicit value를 덮어쓸 수 있다. 동일 속성 충돌 fixture/test로 region, endpoint, credentials, engine의 적용 결과를 검증한다. 외부 주입 client/Operations는 builder 경로를 건너뛴다.
6. 서비스 endpoint는 customizer 적용 후 HTTPS/local HTTP 정책으로 검사한다. 정확한 `localhost`/IPv4 loopback/IPv6 loopback literal만 opt-in에서 HTTP를 허용하고, non-local HTTP는 opt-in이 있어도 거부하며 credential resolve/signing 전에 실패한다. 호출자 주입 client는 endpoint를 검사할 수 없음을 API 문서에 표시한다.
7. IMDS endpoint 제한은 AWS 기본 IPv4/IPv6 주소, HTTPS, opt-in loopback HTTP만 허용한다. env/profile에서 온 원격 HTTP도 첫 token request 전에 거부한다. token·metadata 3xx는 terminal이고 다른 `Location`으로 두 번째 요청이 발생하지 않아 token header가 전달되지 않는다. plugin-owned IMDS engine은 항상 `ProxySelector.NoProxy`를 사용하며 custom proxy selector와 임의 HTTP engine injection은 제공하지 않는다.
8. IMDS는 token TTL/cache/만료 시 갱신, 401 실패와 cache 유지, endpoint/mode와 timeout의 Java precedence, 설치 중 요청 없음, cancellation, plugin engine 소유권을 검증한다. endpoint allowlist를 우회할 수 있는 remote HTTP endpoint, env/system proxy 사용, redirect 또는 hidden connection retry로 인한 추가 요청은 첫 token request 전에 차단되어야 한다. retry matrix는 5xx와 `HttpException.sdkErrorMetadata.isRetryable == true` transport만 재시도하고 3xx/401/기타 4xx/terminal exception/취소는 비재시도다. `CONNECT_TIMEOUT`/`TLS_NEGOTIATION_TIMEOUT` metadata 규칙과 OkHttp의 IOException 매핑(connect/read/socket timeout, TLS 포함)을 고정 Smithy 버전으로 입증한다. `retries=N`은 전체 operation 추가 시도 N회, full-jitter upper bound는 200/400/800/1600/3200/6400/12800ms 후 20초 cap, `retryOnConnectionFailure=false`, 전체 `requestTimeout`을 테스트한다. `SdkHttpClient.call`은 public API이고 `HttpCall.complete()`는 내부 격리된 `@InternalApi` 경계로 모든 완료·오류 cleanup을 검증한다.
9. SQS 회귀·부하 테스트가 최대 동시 처리량, poller별 최대 `maxMessages` batch, long polling, 수신 retry와 SDK retry, handler failure/redelivery, `shutdownTimeout` 뒤 cancel·scope·owned client 종료 순서를 확인한다.
10. Kinesis 테스트가 `ExpiredIteratorException` 뒤 `AfterSequenceNumber` 재획득, `Latest` 초기 구간 예외, iterator/throttle retry 상한과 reset, capped jitter, empty/non-empty poll delay, cold Flow와 취소를 확인한다.
11. CloudWatch Logs 테스트가 timestamp 정렬, chunk 실패/취소 때 drain된 전체 event 복원, 선행 chunk 성공 뒤 가능한 중복, final flush timeout, timeout 정책, dropped count와 owned client close 순서를 확인한다.
12. AWS 서명 벡터와 실제 전송 capture가 credential 회전, session token, 원시 URI/authority, 퍼센트 인코딩, 중복·빈 query/header 값을 검증한다. presigned URL의 만료, payload 생략, HTTPS/local HTTP 정책과 고정 signing time도 확인한다.
13. S3 streaming 검증은 unsigned payload의 비버퍼링, signed byte-array 본문, replay 불가 본문 거부, 본문 중복 소비 없음과 서명 입력/실제 본문 동일성을 확인한다.
14. 기본 signer logging과 redaction 테스트는 Authorization, session token, presigned query, body, secret 값을 로그에서 차단한다.
15. Kotlin external-consumer fixture는 공개 서비스 client/model/customizer 전체, S3 REST, SQS consumer/converter, SigV4와 IMDS를 소비자 classpath에서 compile한다. 다섯 예제 `:aws-ktor-dynamodb-examples:test`, `:aws-ktor-exposed-examples:test`, `:aws-ktor-s3-examples:test`, `:aws-ktor-service-coverage-examples:test`, `:aws-ktor-sqs-examples:test`와 관련 Ktor/emulator 검증이 통과한다.
16. 루트, `aws-ktor`, 다섯 Ktor 예제의 영문·한국어 README가 의존성 및 공개 API/migration 계약을 같은 의미로 설명한다. `CHANGELOG.md` `[미출시] / 변경`에 #659 breaking migration 표와 새 타입 사용 안내가 있다. 이전 #85 결정에는 superseded 안내가 있다. Gradle 의존성 그래프, 발행 metadata와 `git diff --check`는 정확한 브랜치 HEAD에서 검증한다.
17. 상세 매뉴얼 companion 작업의 영문·한국어 페이지가 새 Ktor API로 바뀌고, release tag/peeled commit을 고정한 manifest와 manual validator가 성공하기 전에는 이 변경을 가리키는 release를 만들지 않는다. companion 저장소 작업은 별도 저장소/base/head 및 승인 게이트를 사용한다.
18. 기존 공개 `Serializable` 타입의 marker와 기존에 선언한 `serialVersionUID`를 유지한다. Kinesis value DTO, `SqsPollBackoff`, `SqsFixedFailureVisibilityStrategy`, `SqsConsumerObservation`, `SqsConsumerFailureContext` 등 값 타입은 implementation 전 characterization에서 현재 성공하는 입력을 고정하고 round-trip을 검증한다. 단, 현재 `KinesisPutRecordRequest`의 `SdkBytes` payload는 AWS Java 2.54.12 `BytesWrapper`의 backing field가 직렬화되지 않아 round-trip 뒤 사라진다. migration은 이 동작을 보존하지 않고 저장소 소유 바이트 표현으로 non-empty payload 왕복과 방어 복사를 검증한다. SDK generated model을 포함하는 serial form은 저장소 소유 표현으로 바꾸며 SDK model을 직접 serial form에 넣지 않는다. 사용자 주입 `Random`을 보유하는 `SqsLinearFailureVisibilityStrategy`와 callback/interceptor/observer/converter/dispatcher/client를 포함하는 `SqsConsumerRuntimeConfig`는 marker/UID만 유지하고 해당 실행 객체의 일반 serialization/round-trip을 보장하지 않는다. SDK 모델 교체로 인한 이전 Java serialized bytes의 호환성은 보장하지 않으며, 영향 DTO와 이전 데이터의 비호환성을 `CHANGELOG.md` migration 안내에 기록한다.
19. 독립 최종 코드 검토는 P0=0/P1=0이며 정확한 PR HEAD의 필수 CI가 성공한다. ABI 호환성은 검증 항목이 아니다.

## 범위 밖

- `bluetape4k-aws-java` 또는 `bluetape4k-aws-kotlin` wrapper 기능 추가·재설계
- AWS Spring Boot 공개 API를 Kotlin SDK로 이전
- 외부 AWS Exposed 모듈 구현 변경. 단, 현재 Ktor 선택 통합이 Ktor published metadata에 Java SDK를 재유입하면 범위 예외가 아니라 blocker로 취급한다.
- AWS 서비스 기능 삭제, 새 서비스 통합 또는 새 의존성 버전 train 도입
- PR 병합. 사용자에게 정확한 HEAD의 병합 준비 보고를 전달한 뒤 별도 승인을 받는다.

## 승인 기준과 DoD

사용자는 이슈 #659의 첫 실행 계획과 AWS SDK 경계 재설계 방향을 승인했고 ABI 파괴를 허용했다. 이 승인만으로 구현 계획이나 병합이 승인된 것은 아니다. 구현 전에는 이 문서의 독립 설계 검토에서 P0/P1=0을 확인하고 사용자가 저장된 명세를 검토해야 한다. 그 뒤 구현 계획에 별도 승인을 받아야 한다.

이슈 전체 완료는 구현·문서·테스트가 정확한 PR HEAD에 반영되고 필수 CI가 성공하여 병합 준비 보고까지 제공한 때다. 이 구현 계획의 완료 보고는 PR 생성 전 branch HEAD 검증과 독립 리뷰까지만 증명한다. AC19의 정확한 PR HEAD CI와 review thread read-back은 후속 A-10에서 확인하며, 그전까지 `PENDING`으로 남는다. 병합, develop 동기화, worktree 정리, 정식 GNO 색인 반영은 최신 병합 승인을 받은 뒤 진행한다.

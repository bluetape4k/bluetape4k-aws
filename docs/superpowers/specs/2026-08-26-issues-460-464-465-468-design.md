## 문제와 목표

`aws-spring-boot`는 SQS listener, S3 transfer, DynamoDB Enhanced client를
이미 제공하지만 네 가지 운영 경계가 비어 있다. SQS listener는 receive와
handler 사이의 상한 및 FIFO group 순서를 보장하지 않고, S3에는 close 시
완료되는 출력 스트림·타입 변환기·content type 해석기가 없으며, CRT S3
client 선택과 DynamoDB batch/transaction coroutine 계약도 없다.

이번 train은 기존 `SqsOperations`, `S3TransferOperations`,
`DynamoDbEnhancedAsyncClient`를 재사용하는 additive API를 제공한다. 기본
설정의 동작은 그대로 유지하고, 새 기능은 명시적인 property와 조건부 bean
선택으로만 활성화한다. 모든 blocking SDK 호출은 기존 `Dispatchers.IO` 경계와
coroutine `await()` 확장을 사용한다.

## 현재 근거와 재사용 경계

| 대상 | 현재 근거 | 이번 설계의 재사용 |
|---|---|---|
| SQS | `SqsMessageListenerContainer`, `SqsListenerEndpoint`, #453 heartbeat, #454 batch/partial ack | 기존 generation/handler drain, `SqsReceivedMessage`의 FIFO system attributes, `SqsOperations` SDK adapter |
| S3 | `S3TransferTemplate`, `S3TransferAutoConfiguration`, `S3TransferManagerCoroutinesExtensions.kt` | 기존 `S3TransferManager`, upload/download helper, compileOnly Jackson3 boundary |
| CRT | `gradle/libs.versions.toml`의 `aws2-aws-crt-client` alias | `S3AutoConfiguration`의 region/endpoint/credentials/customizer와 기존 async-client precedence |
| DynamoDB | `DynamoDbEnhancedAsyncClient`, `DynamoDbTableNameResolver`, `AbstractCoroutinesDynamoDbRepository` | Enhanced `TableSchema`, table resolver, CompletableFuture `.await()`, 기존 client lifecycle |
| 테스트 | `ApplicationContextRunner`, MockK, `runTest`, Floci 기본 설정 | deterministic fake를 먼저 사용하고 공유 Docker emulator는 순차 실행 |

공식 AWS SDK/Spring Cloud AWS 자료는 동작 비교에만 사용한다. awspring
dependency는 추가하지 않는다. SQS FIFO group/backpressure와 S3 CRT property
이름은 [Spring Cloud AWS SQS reference](https://docs.awspring.io/spring-cloud-aws/docs/3.4.1/reference/html/index.html),
[S3 CRT properties](https://docs.awspring.io/spring-cloud-aws/docs/3.3.1/apidocs/io/awspring/cloud/autoconfigure/s3/S3CrtAsyncClientAutoConfiguration.html)를
참조하되 bluetape API로 재정의한다.

## 선택한 접근과 대안

### #460 SQS listener

세 가지 선택지를 비교했다.

1. **poller 수만 늘리는 방식**: 구현은 작지만 in-flight 상한과 동일 FIFO
   group 순서를 증명할 수 없어 거부한다.
2. **수신 후 무제한 child job**: 처리량은 높지만 backpressure가 receive보다
   늦게 적용되고 shutdown 시 pending job을 추적하기 어렵다.
3. **bounded admission + group mutex(선택)**: `Semaphore`로 handler 수를
   제한하고 message group별 `Mutex`로 같은 group을 직렬화한다. 다른 group은
   독립적으로 실행하며 기존 generation drain에 job을 등록한다.

queue URL과 `FifoQueue`/`VisibilityTimeout` 등의 속성은
`SqsQueueAttributesResolver`가 조회하고 TTL cache에 저장한다. 조회 실패는
`FAIL_FAST`, `CREATE`, `IGNORE` 정책으로 명시한다. FIFO 여부는 속성 우선,
`.fifo` suffix 보조 순서로 판단한다. batch/partial ack와 heartbeat는 기존
경로를 호출하며 중복 scheduler를 만들지 않는다.

### #464 S3 stream/converter

무제한 `ByteArray` 누적, custom `AsyncRequestBody` pipe, 임시 파일 spool을
비교했다. pipe는 close·취소·client lifecycle을 동시에 증명하기 어렵고
무제한 누적은 large upload 계약을 위반한다. **bounded temp-file spool을
선택**한다. `S3OutputStream`은 threshold 전까지 memory buffer를 사용하고
threshold를 넘으면 동일 파일로 전환한다. `close()`는 upload completion을
기다리고 성공/실패와 temp file cleanup을 결정적으로 마친다. 실제 upload는
기존 `S3TransferTemplate`/`S3TransferManager`를 사용한다.

`S3ObjectConverter<T>`는 `write(T): ByteArray`,
`read(InputStream, Class<T>)`, `contentType(): String?` 계약을 갖고,
Jackson3가 classpath에 있을 때만 기본 converter bean을 등록한다.
호출자 지정 content type > converter content type > key 확장자
`Files.probeContentType` > `application/octet-stream` 순서로 해석한다.

### #465 CRT S3 client

항상 CRT를 선택하거나 별도 `S3AsyncClient`를 병렬 생성하는 방식은 기존
client precedence와 lifecycle을 깨므로 거부한다. `aws-crt-client` class가
존재하고 `bluetape4k.aws.s3.crt.enabled=true`일 때만
`S3CrtAsyncClientAutoConfiguration`이 동작한다. 사용자가
`S3AsyncClient`를 제공하면 back-off하고, CRT class가 없거나 property가
비활성화되면 기존 async client를 그대로 사용한다. throughput,
maxConcurrency, minimumPartSize, checksum 설정은 immutable validated
properties로 제한하며 manager가 CRT client를 소유하지 않는 경우 close하지
않는다.

### #468 DynamoDB

저장소마다 batch/transaction을 복제하는 방식은 table schema와 오류 모델이
분산되므로 거부한다. `DynamoDbTemplate`이 resolver로
`DynamoDbTable<T>`를 얻고 `get/put/delete/update`, `batchGet/batchWrite`,
`transactGet/transactWrite`를 coroutine API로 제공한다. entity class별
`TableSchema`와 resolved table name을 bounded concurrent cache에 저장하고,
호출자 명시 이름 > resolver > global prefix 순서를 지킨다. SDK의
unprocessed items는 `DynamoDbBatchResult`에 남겨 부분 실패를 숨기지 않으며
취소는 `CancellationException`을 재전파하고 이미 생성된 publisher/subscription을
정리한다. DAX client와 표준 enhanced client는 서로의 bean 조건을 침범하지
않는다.

## 공통 오류·수명·호환성

- public DTO는 immutable이며 입력 `ByteArray`와 attributes를 clone한다.
- `require*` 검증은 외부 AWS 호출 전에 수행한다. 실패 진단에는 payload,
  credentials, URL 전체를 넣지 않는다.
- `close`, `stop`, coroutine cancellation은 idempotent하다. Spring이 만든
  client/manager는 해당 auto-config가 소유한 경우에만 닫는다.
- 기존 bean 우선순위와 property 기본값은 유지한다. 새 compileOnly SDK 외에
  의존성을 추가하지 않는다.
- Floci를 먼저 실행하고 capability gap이 있으면
  `-Dbluetape4k.aws.emulator=localstack`을 명시적으로 재실행한다. 자동
  fallback은 허용하지 않는다.

## 실패 모드와 대응

| 실패 | 관찰 가능한 결과 | 대응 |
|---|---|---|
| SQS in-flight cap 초과/stop timeout | 새 receive가 중단되고 미완료 handler 수가 기록됨 | generation drain 후 timeout이면 남은 job을 cancel하고 client는 Spring lifecycle에 맡김 |
| 동일 FIFO group 동시 실행 | group mutex가 predecessor completion 전 다음 handler를 허용하지 않음 | mutex map을 generation 수명에 묶고 완료 후 제거 |
| queue attribute/queue URL 미존재 | 정책에 따른 fail/create/ignore와 redacted exception | cache에는 성공 값만 저장하고 실패 값을 오염시키지 않음 |
| S3 stream upload/close 실패 | completion future 오류와 temp file cleanup 결과를 함께 반환 | 재시도 가능한 key/파일 경로만 진단에 남김 |
| CRT classpath/property 충돌 | context가 fail-fast 또는 기존 client로 결정 | user-defined `S3AsyncClient`는 항상 우선하고 manager close를 중복하지 않음 |
| DynamoDB unprocessed/transaction/cancellation | typed batch result 또는 재전파된 취소 | partial result를 버리지 않고 publisher/subscription을 취소 |

## 범위와 제외

포함 범위는 `aws-spring-boot`의 public Kotlin API, auto-configuration,
unit/fake/Floci tests, KDoc와 필요한 README/config 예시다. Spring Integration,
KCL, awspring 의존성, 새 공통 retry framework, 실제 AWS credential/production
배포, PR 생성·merge·release는 제외한다.

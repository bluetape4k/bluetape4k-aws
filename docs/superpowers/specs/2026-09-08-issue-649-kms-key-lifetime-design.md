# #649 KMS 평문 데이터 키의 소유권과 소거

## 목표와 승인 범위

이슈 #649의 승인된 구현이다. `develop`에서 분리한 `feat/issue-649-kms-key-lifetime`으로 PR을 생성하고 머지는 보류한다. 공개 생성자와 기존 메서드 서명은 유지한다. 새 의존성은 추가하지 않는다.

## 소유권 계약

- `KmsDataKey`는 `AutoCloseable`을 구현한다. 내부 평문 배열은 객체가 소유하며 `close()`가 멱등적으로 소거한다. 닫힌 객체에서 평문을 읽으면 실패한다. 암호화된 키와 메타데이터는 계속 읽을 수 있다.
- 평문 getter와 내부 복사 연산, close는 같은 잠금으로 직렬화한다. 복사와 close가 경합해도 부분적으로 소거된 키를 반환하지 않는다.
- `DataKeyCache.put`은 호출자 소유권을 이전받지 않는다. 캐시는 독립 복사본을 소유한다. `get`은 호출자가 닫아야 하는 독립 복사본을 반환한다. 사용자 정의 캐시도 이 계약을 따라야 한다. 기존 동일 인스턴스 반환은 더 이상 계약이 아니다.
- `InMemoryDataKeyCache`는 교체, 크기 축출, 만료 확인, 명시적 evict/clear 시 캐시 소유 키를 닫는다. TTL은 기존처럼 접근 시 검사하며 백그라운드 소거 시각을 보장하지 않는다.
- 이미 발급된 호출자 복사본은 캐시 변경으로 무효화되지 않는다. `NoopDataKeyCache`는 소유하지 않으며 입력을 닫지 않는다.

## 사용 경로

`KmsCoroutinesEncryptor.generateDataKey`는 SDK로부터 얻은 평문 임시 배열을 방어적 복사 후 finally에서 소거한다. 캐시 저장 실패 시 반환되지 못한 생성 키도 닫는다. 캐시 조회 결과는 위 계약에 따른 호출자 소유 객체다. 임의 사용자 정의 캐시의 공유 객체를 감지하거나 자동 보정하지 않는다.

S3 KMS 암호화 업로드는 생성한 호출자 키를 use로 닫고 getter가 반환한 임시 평문을 finally로 소거한다. 일반 및 제한 다운로드는 KMS decrypt가 반환한 평문 키를 복호화 성공/실패에 관계없이 finally에서 소거한다. 코루틴 취소를 삼키지 않는다. AWS 클라이언트 및 호출자의 원본 콘텐츠 소유권은 바꾸지 않는다.

## 대안과 한계

참조 카운트와 공유 가변 키 대신 독립 소유 복사를 선택한다. 복사 비용은 증가하지만 퇴출과 진행 중 암호화의 수명 경합을 제거한다. 새로운 timer나 전역 자원 계층은 추가하지 않는다. JVM, JCE, SDK 내부 복사본과 GC 메모리의 완전한 소거는 보장할 수 없다. 라이브러리가 소유하는 배열만 명시적으로 소거한다.

## 검증 기준

캐시 조회 독립성 회귀를 먼저 실패시킨다. 이어서 close 멱등성/접근 거부, 원본 배열 보존, TTL/LRU/교체/evict/clear의 내부 배열 소거, 발급된 복사본 생존, copy-close 경합을 검증한다. S3 정상/실패 경로에서 소비된 키 소거를 확인하고 기존 암호화 round trip과 emulator 테스트를 실행한다. ABI 검사 및 관련 모듈 test/build/detekt 결과를 PR에 명시한다.

## 독립 검토 반영

Spring이 생성한 `DataKeyCache` Bean은 `destroyMethod = "clear"`로 context 종료 시 보유 키를 소거한다. 외부에서 제공하는 사용자 정의 Bean의 수명은 제공자가 관리한다. 크기 축출은 명시적 제거와 close로 구현하여 `removeEldestEntry`의 조용한 제거에 의존하지 않는다.

`KmsOperations.generateDataKey`는 호출자에게 독립 키 소유권을 넘긴다고 KDoc과 use 예제로 명시한다. `decrypt`의 반환 배열도 호출자가 변경/소거할 수 있는 소유 배열이다. 사용자 정의 KmsOperations/캐시는 공유 객체 반환을 독립 복사로 이관해야 한다. 생성자에 넘긴 원본 배열은 호출자 소유이며 생성자가 지우지 않는다.

실패 및 취소 전파는 생성 이후 업로드 future 실패/취소를 포함해 테스트한다. 다운로드의 키 발급 이후 복호화는 suspend 없는 구간이므로 finally 소거를 성공/인증 실패로 검증하며, AWS 대기 취소 시 키가 아직 발급되지 않았음을 검증한다. 존재하지 않는 suspension 지점을 가정하지 않는다.

안정성/성능 보강: get의 cache-owned 키 복사는 cache lock 안에서 완료한다. 퇴출은 같은 lock 안에서 map에서 분리하고, 분리된 키의 close는 lock 밖에서 실행한다. put의 독립 복사본이 삽입 실패로 소유자를 얻지 못하면 finally에서 닫는다. cache lock으로 JCE 암호화나 AWS await를 감싸지 않는다. 동시 get/evict/put 테스트로 닫힌 키 노출 및 부분 소거가 없음을 검증한다.

운영 이관: lazy TTL은 보안상 최대 보존시간이 아니다. 유휴 캐시에는 만료 키가 남을 수 있으며 엄격한 보존 상한이 필요한 호출자는 캐시를 비활성화하거나 제공자 소유의 명시적 clear 정책을 사용한다. 외부 캐시 제공자는 종료 시 clear를 직접 호출하고 통합 테스트로 확인해야 한다. 새 use/close 호출 코드와 구버전 라이브러리를 혼용하지 않으며 배포·롤백은 애플리케이션과 라이브러리를 포함한 전체 릴리스 단위로 수행한다. 사용자 정의 캐시는 이관 점검에서 put/get 독립성 및 close 후 다음 get 정상 동작을 확인한다.

캐시 put 실패 계약: 구현은 새 snapshot을 publish하기 전 실패 가능 작업을 완료하고, put이 예외로 끝나면 해당 시도의 새 키를 보유하지 않아야 한다. 실패 중 생성한 snapshot은 캐시 구현이 소거한다. encryptor는 사용자 정의 캐시 내부 저장소에 접근하지 않으며 캐시의 실패 원자성 위반을 복구한다고 주장하지 않는다. fault-injecting 캐시 fixture와 InMemory의 삽입 전 clock 실패로 새 키 무보유 및 호출자 키 보존을 검증한다.

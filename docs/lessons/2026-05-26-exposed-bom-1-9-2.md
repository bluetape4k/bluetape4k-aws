# Consume Released bluetape4k Exposed BOM 1.9.2

## Context

`bluetape4k-aws` had already moved the main bluetape4k BOM to the released
`1.9.2` line, while the Exposed helper BOM still referenced
`1.9.2-SNAPSHOT`.

## Decision

Switch the `bluetape4k-exposed` version catalog entry to the released
`io.github.bluetape4k.exposed:bluetape4k-exposed-bom:1.9.2` artifact. Keep the
existing module-level BOM imports so only Exposed-aware modules consume the
Exposed helper alignment.

## Outcome

The Exposed helper dependency line now resolves from Maven Central stable
artifacts instead of the snapshot repository.

## Verification

- Maven Central POM check: `bluetape4k-exposed-bom:1.9.2` returned HTTP 200.
- `./gradlew --no-daemon --max-workers=1 :bluetape4k-aws-exposed:compileKotlin :aws-spring-boot-exposed-examples:compileKotlin :aws-ktor-exposed-examples:compileKotlin`
  completed successfully.
- `./gradlew --no-daemon --max-workers=1 :bluetape4k-aws-exposed:dependencyInsight --configuration compileClasspath --dependency bluetape4k-exposed-bom`
  resolved `io.github.bluetape4k.exposed:bluetape4k-exposed-bom:1.9.2`
  with Gradle status `release`.

## Future Guard

When a bluetape4k release train moves from snapshot to stable, check both the
main BOM and specialized helper BOMs such as `bluetape4k-exposed-bom`; they may
stabilize on different timing.

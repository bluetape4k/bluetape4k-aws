# PR #656 리팩터링 리뷰에서 다시 확인한 호환성·자원 소유권 가드

## 배경과 놓친 점

기존 교훈은 공개 Kotlin 변경에서 JVM 생성자 descriptor를 보존하고, Ktor plugin이 만든 client만 plugin lifecycle에서 닫으며, 진단 문자열에서 credential을 숨기도록 안내했다. 그런데 PR #656의 후속 독립 리뷰에서 해당 규칙이 변경된 모든 공개 타입과 실제 설정 상속 경로에 적용되지 않은 사례가 발견됐다. 기존 교훈이 있다는 사실만으로 회귀 방지 검증이 수행됐다고 볼 수 없었다.

## 수정한 결정

- 공개 클래스의 생성자나 기본 인자를 바꾸면 변경된 모든 공개 타입의 JVM 생성자 descriptor를 비교한다. 주 생성자만 확인하지 말고 이전 호출 형태를 보존하는 secondary constructor와 reflection/consumer ABI fixture를 함께 둔다.
- plugin 소유 AWS client와 호출자 소유 HTTP 엔진은 별도로 추적한다. 명시적 plugin 설정 또는 공유 기본 엔진이 있으면 엔진은 호출자 소유다. 둘 다 없으면 SDK가 만든 엔진을 SDK client가 정리한다. 공유 엔진 구성에서는 서비스 client를 모두 닫은 뒤 엔진을 닫는다.
- `toString()`에는 외부 설정 값, endpoint, credential, provider/customizer 객체, 메시지 본문을 출력하지 않는다. 값 대신 설정 여부, 개수, 안전한 key만 출력하고 sentinel 테스트로 민감값 부재를 확인한다.
- CI job 일부가 성공했더라도 필수 job이 취소됐거나 aggregate status가 실패하면 run을 녹색으로 취급하지 않는다. 변경을 push한 뒤 최종 PR SHA의 필수 체크 전체를 다시 확인한다.

## 검증 근거와 한계

후속 수정은 `227e492ed42f7c5e51047a53fa33ddc7f962fada`에 반영됐다. 공개 생성자 reflection 테스트, Ktor 설정/종료 테스트, redaction 테스트, Floci DynamoDB runtime 테스트가 통과했고 독립 code review 및 architecture review는 P0/P1/P2를 0건으로 판정했다. 이전 run `39165049180`에서는 `Test / aws-ktor emulator examples`가 30분 후 취소되어 aggregate CI가 실패했다. 따라서 부분 성공은 전체 CI 성공을 대신하지 않았다.

전체 `detekt`는 변경되지 않은 기준 코드의 기존 9개 지적으로 실패했으며 PR 회귀와 구분했다. 이 교훈을 닫을 때는 KDoc·문서 후속 커밋까지 포함한 최종 PR SHA의 필수 CI 결과와 live review/thread 상태를 별도로 확인해야 한다.

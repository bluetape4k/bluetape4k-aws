# Issue #203 Ktor Advanced S3 Helpers

## Context

`aws-ktor` already had a REST-first `S3KtorClient` for core object operations.
Issue #203 asked for advanced S3 helpers while keeping basic S3 usage free of
mandatory service-client dependencies.

## Decision

Add opt-in helpers on top of the existing REST client instead of introducing
S3 Control, S3 Vector, or KMS SDK dependencies into the default API surface.
Client-side encryption uses a data-key provider interface so applications can
wire KMS where needed without forcing that dependency on all users.

## Outcome

- Added content-type detection upload helper.
- Added server-side encryption header models for SSE-S3, SSE-KMS/DSSE-KMS,
  bucket keys, and SSE-C.
- Added AES-GCM client-side envelope encryption with S3 metadata storage for
  encrypted data keys and nonces.
- Added S3 text config object put/get helpers.
- Added Floci-backed S3 round-trip coverage.
- Added README architecture and sequence diagrams as SVG sources and PNG embeds.

## Future Guard

Do not add S3 Access Grants or S3 Vector SDK clients to `aws-ktor` as mandatory
runtime dependencies. Keep them optional or application-owned until the service
APIs and dependency footprint are stable enough for a wrapper.

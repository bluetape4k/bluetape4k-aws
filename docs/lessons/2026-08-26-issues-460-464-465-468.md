# 이슈 #460·#464·#465·#468 AWS Spring Boot train lesson

## 배경

사용자 승인(`승인`) 후 `aws-spring-boot`의 네 운영 경계를 이슈 순서대로
구현했다. 범위는 기존 bluetape4k SQS/S3/DynamoDB 계약과 AWS SDK v2를
재사용하는 additive API, 자동 구성, 단위·에뮬레이터 테스트였으며 PR·merge·release는
포함하지 않았다.

## 결정 또는 발견 사항

- #460은 기존 listener generation에 `Semaphore` admission과 group별 `Mutex`를
  연결했다. 기본 admission은 `maxMessages × concurrency`로 두어 기존 polling
  동시성을 보존하고, 명시한 `maxInFlight`만 고정 상한으로 적용한다. queue
  attributes는 성공 결과만 TTL cache에 저장하며 FIFO group과 not-found 정책을
  별도 enum으로 노출했다.
- #464는 기존 `S3TransferManager` 경계 위에 threshold 기반 memory/temp-file
  `S3OutputStream`, typed converter, content-type resolver를 추가했다. close는
  completion을 기다리고 임시 파일을 정리하며, blocking 경계는 `Dispatchers.IO`에
  둔다.
- #465는 CRT SDK가 classpath에 있고 `bluetape4k.aws.s3.crt.enabled=true`일 때만
  CRT async client를 선택한다. 사용자가 제공한 `S3AsyncClient`와 기존
  credentials/endpoint/customizer 경계는 우선한다.
- #468은 기존 `DynamoDbEnhancedAsyncClient`와 table-name resolver를 재사용하는
  `DynamoDbTemplate`으로 CRUD, batch get/write, transaction get/write를
  coroutine API로 통합했다. schema와 physical table은 cache하고, unprocessed
  item·transaction 원인·cancellation은 호출자에게 숨기지 않는다.
- SQS 새 property가 기존 precompiled consumer의 constructor descriptor를
  바꾸는 회귀를 일으켰다. legacy secondary constructor를 추가하고 ABI fixture를
  통과시켜 additive 변경 경계를 복구했다.

## 향후 지침

Kotlin data class property를 public configuration에 추가할 때는 source
호환성만 보지 말고 precompiled constructor descriptor fixture를 함께 확인한다.
listener admission의 기본값은 기존 `concurrency`와 deadlock 가능성을 먼저
검토한다. AWS SDK 선택형 client는 classpath/property/user bean precedence와
lifecycle ownership을 한 테스트 묶음으로 유지한다. batch API는 성공 결과만
반환하지 말고 SDK의 partial result와 cancellation/error cause를 typed result 또는
원인 보존 예외로 전달한다.
